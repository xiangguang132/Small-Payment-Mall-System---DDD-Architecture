# 函数式数据缓存技术调研 — 本地化改造方案

> 调研日期：2026-08-20
> 源项目：`D:\code\group-buy-market`（group-buy-market 参考工程）
> 目标项目：`D:\code\s-pay-mall-ddd-cc`

---

## 一、源项目技术概览

### 1.1 核心思路

用一个 **泛型方法 + `Supplier<T>` 延迟执行** 替代所有 `if (缓存有) { return } else { 查库; 写缓存 }` 的模板代码。DB 回退查询以 lambda 形式传入，仅在缓存未命中时才执行。

### 1.2 完整调用链

```text
营销大厅查询 queryGroupBuyActivityDiscountVO(activityId)
  └─ ActivityRepository (extends AbstractRepository)
       └─ getFromCacheOrDb(key, () -> dao.query...(activityId))
            ├─ DCC 开关 ON → Redis 命中 → 直接返回
            │                 → Redis 未命中 → 查库 → setValue 写回 → 返回
            └─ DCC 开关 OFF → logger.warn → 直查 DB（降级）
```

### 1.3 关键组件

| 组件 | 模块 | 职责 |
|---|---|---|
| `AbstractRepository` | infrastructure/adapter/repository | 封装 `getFromCacheOrDb`，核心方法 |
| `DCCService` | infrastructure/dcc | 读取 `@DCCValue("cacheSwitch:0")` 动态开关 |
| `IRedisService` / `RedissonService` | infrastructure/redis | Redis 底层读写（RBucket，泛型序列化） |
| PO 上的 `cacheRedisKey()` | infrastructure/dao/po | 静态方法生成 `前缀_全限定类名_业务ID` 格式的 key |

### 1.4 核心源码

```java
// AbstractRepository.java — 源项目
protected <T> T getFromCacheOrDb(String cacheKey, Supplier<T> dbFallback) {
    if (dccService.isCacheOpenSwitch()) {
        T cacheResult = redisService.getValue(cacheKey);
        if (null != cacheResult) {
            return cacheResult;
        }
        T dbResult = dbFallback.get();
        if (dbResult == null) return null;
        redisService.setValue(cacheKey, dbResult);
        return dbResult;
    } else {
        logger.warn("缓存降级，未开启：{}", cacheKey);
        return dbFallback.get();
    }
}

protected <T> T getFromCacheOrDb(String cacheKey, Supplier<T> dbFallback, long expired) {
    // 同上，写缓存时带过期时间
    redisService.setValue(cacheKey, dbResult, expired);
}
```

### 1.5 Cache Key 设计

```java
// PO 实体上定义的静态方法
public static String cacheRedisKey(Long activityId) {
    return "group_buy_market_cn.bugstack.infrastructure.dao.po.GroupBuyActivity_" + activityId;
}
```

- 格式：`{项目前缀}_{类全限定名}_{业务ID}`
- 全限定类名充当"虚拟表名"，防止 key 冲突
- 生成规则集中在 PO 上，保证查/写/删用同一套 key

### 1.6 动态开关（DCC）

| cacheSwitch 值 | 含义 |
|---|---|
| `0`（默认） | 缓存开启 |
| `1` | 缓存关闭，全局降级到 DB |

通过 Redis Pub/Sub 热更新，无需重启。

## 二、目标项目现状分析

### 2.1 已有基础设施

| 能力 | 现状 | 位置 |
|---|---|---|
| Redis 客户端 | **Redisson** (`redisson-spring-boot-starter 3.26.0`) | infrastructure/redis |

| Repository 缓存模式 | **手写 cache-aside**（get→miss→查库→set），散落在各 Repository 中 | infrastructure/repository |

### 2.2 现有 Repository 缓存代码（需要改造的部分）

当前各 Repository **各自手写** cache-aside 逻辑，例如：

```java
// MaterialRepository — 当前写法
MaterialAggregate cacheResult = redisService.get(cacheKey, MaterialAggregate.class);
if (cacheResult != null) return cacheResult;
MaterialPO materialPO = materialDao.queryById(id);
// ... 组装 → redisService.set(cacheKey, aggregate);
```

**问题：**
1. 每个 Repository 重复 `get → null check → 查库 → set` 模板
2. 没有统一的动态降级开关
3. 没有统一的 TTL 管理策略
4. 缓存 key 命名规范不统一（有的用 `s-pay-mall:material:id:`，有的格式不同）

## 三、本地化改造方案

### 3.1 改造范围

```
infrastructure/
  └─ adapter/repository/
       └─ AbstractRepository.java          ← 新增（核心）
  └─ redis/
       └─ IRedisService.java               ← 补充 remove 方法（如有缺失）
  └─ dcc/
       └─ DCCService.java                  ← 补充 cacheSwitch 字段（如未配置）
  └─ repository/                            ← 逐个改造现有 Repository
       ├─ MaterialRepository.java
       ├─ CrowdTagsRepository.java
       ├─ CrowdTagsDetailRepository.java
       └─ GroupBuyActivityRepository.java
```

### 3.2 Step 1：新增 AbstractRepository

位置：`s-pay-mall-ddd-infrastructure/src/main/java/cn/bugstack/infrastructure/adapter/repository/AbstractRepository.java`

```java
package cn.bugstack.infrastructure.adapter.repository;

import cn.bugstack.infrastructure.dcc.DCCService;
import cn.bugstack.infrastructure.redis.IRedisService;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import javax.annotation.Resource;
import java.util.function.Supplier;

/**
 * Repository 抽象基类
 * 封装函数式缓存 + DB 降级，子类通过 getFromCacheOrDb 统一缓存操作
 */
public abstract class AbstractRepository {

    private final Logger logger = LoggerFactory.getLogger(getClass());

    @Resource
    protected IRedisService redisService;

    @Resource
    protected DCCService dccService;

    /**
     * 通用缓存查询：优先读缓存，未命中则执行 dbFallback 查库并回填
     *
     * @param cacheKey  缓存 key
     * @param dbFallback 数据库兜底查询（延迟执行）
     */
    protected <T> T getFromCacheOrDb(String cacheKey, Supplier<T> dbFallback) {
        if (dccService.isCacheOpenSwitch()) {
            T cacheResult = redisService.get(cacheKey);
            if (null != cacheResult) {
                return cacheResult;
            }
            T dbResult = dbFallback.get();
            if (null == dbResult) {
                return null;
            }
            redisService.set(cacheKey, dbResult);
            return dbResult;
        } else {
            logger.warn("缓存降级，未开启：{}", cacheKey);
            return dbFallback.get();
        }
    }

    /**
     * 通用缓存查询（带过期时间）
     */
    protected <T> T getFromCacheOrDb(String cacheKey, Supplier<T> dbFallback, long expired) {
        if (dccService.isCacheOpenSwitch()) {
            T cacheResult = redisService.get(cacheKey);
            if (null != cacheResult) {
                return cacheResult;
            }
            T dbResult = dbFallback.get();
            if (null == dbResult) {
                return null;
            }
            redisService.set(cacheKey, dbResult, expired);
            return dbResult;
        } else {
            logger.warn("缓存降级：{}", cacheKey);
            return dbFallback.get();
        }
    }
}
```

> **注意**：方法签名调用的是目标项目 `IRedisService` 已有的 `get`/`set` 方法，而非源项目的 `getValue`/`setValue`。具体方法名需以实际接口为准。

### 3.3 Step 2：补充 DCCService 缓存开关

确认 `DCCService` 中有 `cacheSwitch` 字段和 `isCacheOpenSwitch()` 方法。如果没有，需要补充：

```java
@DCCValue("cacheSwitch:0")
private String cacheOpenSwitch;

public boolean isCacheOpenSwitch() {
    return "0".equals(cacheOpenSwitch); // 0=开启, 1=关闭
}
```

### 3.4 Step 3：在 PO 实体上定义 cacheRedisKey()

以 `MaterialPO` 为例：

```java
// MaterialPO.java
public static String cacheRedisKey(Long materialId) {
    return "s-pay-mall:material:id:" + materialId;
}
```

> 复用现有 key 前缀 `s-pay-mall:material:id:` 保持与已运行缓存兼容。

### 3.5 Step 4：改造现有 Repository（以 MaterialRepository 为例）

**改造前（手写 cache-aside）：**

```java
public MaterialAggregate queryById(Long materialId) {
    String cacheKey = "s-pay-mall:material:id:" + materialId;
    MaterialAggregate cacheResult = redisService.get(cacheKey, MaterialAggregate.class);
    if (cacheResult != null) return cacheResult;
    MaterialPO materialPO = materialDao.queryById(materialId);
    if (null == materialPO) return null;
    MaterialAggregate aggregate = new MaterialAggregate(/* ... */);
    redisService.set(cacheKey, aggregate);
    return aggregate;
}
```

**改造后（函数式缓存）：**

```java
public class MaterialRepository extends AbstractRepository {

    public MaterialAggregate queryById(Long materialId) {
        return getFromCacheOrDb(
            MaterialPO.cacheRedisKey(materialId),
            () -> {
                MaterialPO materialPO = materialDao.queryById(materialId);
                if (null == materialPO) return null;
                return new MaterialAggregate(/* ... */);
            }
        );
    }
}
```

**变化点：**
- 移除手写的 `redisService.get` / `null check` / `redisService.set` 模板
- DB 查询逻辑封装为 `Supplier` lambda
- 降级开关由 `AbstractRepository` 统一处理

## 四、使用边界判断

> 核心原则：**读多、写少、数据变化慢、不依赖实时状态 → 适合缓存**

| Repository | 查询 | 适合缓存？ | 理由 |
|---|---|---|---|
| MaterialRepository | 按 ID/Code 查物料 | ✅ | 物料主数据，极少变更 |
| GroupBuyActivityRepository | 按 ID 查活动（含标签） | ✅ | 活动配置，读多写少 |
| CrowdTagsRepository | 人群包元数据查询 | ✅ | 标签配置读多写少 |
| CrowdTagsDetailRepository | BitSet 人群明细 | ⚠️ 已用 Redis Bitmap | 不需要额外缓存层 |
| GroupBuyActivityRepository (withTag) | 带标签的活动列表 | ⚠️ 视查询模式 | 复杂查询结果缓存需谨慎 |
| 支付/订单相关 Repository | 下单、回调路径 | ❌ | 写路径 + 实时状态，不可缓存 |
| AlipayNotifyTaskRepository | 通知任务查询 | ❌ | 需要最新状态，写路径 |

## 五、与源项目的差异点

| 维度 | 源项目 (group-buy-market) | 目标项目 (s-pay-mall-ddd-cc) | 影响 |
|---|---|---|---|
| Redis 服务方法名 | `getValue` / `setValue` | `get` / `set` | 方法签名适配 |
| Redis 服务泛型 | `IRedisService` 泛型 `<T>` get/set（直接返回对象） | `IRedisService` 泛型 get/set（JSON 序列化/反序列化） | 需确认目标项目 `get(key)` 无 class 参数时是否可用 |
| DCC 依赖 | `xfg-wrench-bom` 外部包 | 同源 `@DCCValue` | 直接复用 |
| Repository 基类 | 已有 `AbstractRepository` | **需新建** | 新增文件 |
| 已有缓存代码 | 仅 `ActivityRepository` 用了缓存 | 多个 Repository 已手写 cache-aside | 改造范围更大 |

### ⚠️ 关键适配点：IRedisService.get 签名

源项目 `IRedisService.getValue(String key)` 直接返回 `<T>`。
目标项目 `IRedisService.get(String key, Class<T> clazz)` 需要传 Class 类型。

**两种适配方案：**

**方案 A：AbstractRepository 中多提供一个重载**
```java
protected <T> T getFromCacheOrDb(String cacheKey, Class<T> clazz, Supplier<T> dbFallback) {
    // 用 redisService.get(cacheKey, clazz) 替代 redisService.get(cacheKey)
}
```
调用时传入类型：`getFromCacheOrDb(key, MaterialAggregate.class, () -> dao.query(...))`

**方案 B：给 IRedisService 补一个不带 Class 的 get 方法**
```java
// IRedisService 新增
<T> T get(String key);
// RedissonService 实现
public <T> T get(String key) {
    return redissonClient.<T>getBucket(key).get();
}
```

> **推荐方案 B**：更干净，AbstractRepository 不需要携带 Class 参数，保持与源项目一致的简洁调用风格。

## 八、风险与注意事项

1. **缓存与写路径隔离**：严禁在下单、支付回调等写路径上使用缓存查询，避免脏读。
2. **不同查询条件不可共用 key**：如 `queryValidGroupBuyActivityId`（带 status=1 过滤）和 `queryGroupBuyActivityByActivityId`（无过滤）必须用不同 key。
3. **降级兜底**：DCC 开关默认值为 `0`（缓存开启），Redis 不可用时需配合开关快速降级。
4. **缓存一致性**：将来加配置后台时，写库成功后必须同步删缓存。
5. **Logger 使用 `getClass()` 而非硬编码类名**：子类继承时日志能正确标识来源。
