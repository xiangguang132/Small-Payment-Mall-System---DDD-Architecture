# 人群标签任务自动执行说明

更新时间：2026-08-13

## 问题

当前“人群标签任务”没有自动执行入口。系统不会在后台定时读取 `crowd_tags_job` 并自动采集人群，必须手动调用：

```java
tagService.execTagBatchJob(tagId, batchId);
```

目前全项目中，`execTagBatchJob` 只被测试类调用，没有定时任务或后台管理入口触发。

## 当前现状

- 数据库已存在 `crowd_tags`、`crowd_tags_detail`、`crowd_tags_job` 三张表。
- `crowd_tags` 是人群标签配置元数据。
- `crowd_tags_job` 是人群计算任务配置，记录规则、批次、统计时间范围和状态。
- `crowd_tags_detail` 是人群成员明细。
- `TagService.execTagBatchJob` 已具备写入 `crowd_tags_detail` 和 Redis `RBitSet` 的能力。
- `CrowdTagsExecuteService` 中的“采集用户信息”仍是 TODO，目前写死 `xiaofuge`、`liergou`。
- 项目已经开启 `@EnableScheduling`，具备新增 Spring 定时任务的条件。

## 当前调用链路

```text
测试或手动代码
  -> TagService.execTagBatchJob(tagId, batchId)
  -> 生成 userId 列表（当前是写死用户）
  -> 写入 crowd_tags_detail
  -> 写入 Redis RBitSet[tagId]
```

运行期拼团试算时，不会查 `crowd_tags_detail`，而是通过 Redis BitSet 判断用户是否命中人群。

## 期望执行链路

后台管理人工配置：

```text
crowd_tags       配置人群标签属性
crowd_tags_job   配置本次任务规则、统计时间范围、状态
```

系统自动执行：

```text
定时任务或后台触发
  -> TagService.execTagBatchJob(tagId, batchId)
  -> 查询 crowd_tags_job
  -> 按 tag_type / tag_rule / 统计时间范围采集 userId 列表
  -> 写入 crowd_tags_detail
  -> 写入 Redis RBitSet[tagId]
  -> 更新 crowd_tags.statistics
```

## 自动执行方案建议

在 `s-pay-mall-ddd-trigger` 模块新增定时任务，参考现有 `ProductionOrderJob` 的方式：

```java
@Component
public class CrowdTagJob {

    @Resource
    private ITagService tagService;

    @Scheduled(cron = "${crowd.tag.job.cron:0 0/10 * * * ?}")
    public void exec() {
        // batchId 建议按时间生成，例如 yyyyMMddHHmmss
        tagService.execTagBatchJob("需要配置的tagId", "需要生成的batchId");
    }
}
```

也可以做成后台管理接口，由运营人员手动触发指定 `tagId` 的任务，而不是只依赖定时任务。

## 当前还不能称为“自动采集”的原因

1. `TagService.execTagBatchJob` 没有查询 `crowd_tags_job`。
2. 没有根据 `tag_type`、`tag_rule`、统计时间范围计算用户。
3. 没有生成真实批次号的逻辑。
4. 没有定时任务或后台触发入口。

因此目前只能算“测试数据灌入”，不能算生产级人群自动采集。

## 后续建议测试点

- `crowd_tags_job`：按 `tagId + batchId` 查询任务。
- `crowd_tags_detail`：写入明细，重复写入幂等。
- Redis BitSet：存在、不存在、命中、未命中。
- `TagNode`：`tagScope` 为 1、2、1,2 时的可见和参与限制。
- TAG 专属优惠：命中用户享受优惠，未命中用户返回原价。
- 后续 CRUD：`crowd_tags` 配置的新增、修改、查询和 `tag_id` 唯一性。
