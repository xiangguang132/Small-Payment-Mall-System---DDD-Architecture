## 2. 当前结算模型

当前代码模型是“每次支付成功即进行结算累加”：

```text
支付成功
  -> 查 group_buy_order
  -> 查 group_buy_team
  -> 校验订单状态、支付时间
  -> 更新 group_buy_order.status = 1
  -> group_buy_team.complete_count + 1
  -> 如果 complete_count + 1 == target_count
       -> group_buy_team.status = 1
       -> complete = true
```

这不是“先只标记支付，再异步等成团后统一结算”，而是：

- 每次支付回调都立即处理当前订单。
- 每次支付都会累加团队完成人数。
- 只有最后一人支付时才把团队状态置为成团。

## 4. 关于发起者字段

`GroupBuySettlementFeedBackEntity` 不需要保存 `initiatorUserId/createTime/updateTime`。

结算服务构建的 `GroupBuyTeamEntity` 只是“结算前团队快照”，后续仓储更新只依赖：

- `teamId`
- `targetCount`
- `completeCount`
- `status`

所以不需要为了结算而把发起者、创建时间、更新时间塞进反馈实体。
