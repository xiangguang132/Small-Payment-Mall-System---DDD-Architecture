# 成团通知 — 参考实现（定版）

> 用途：成团后**通知用户**（站内信）。
> 方案（已多次对齐确认）：**拼团专用任务表 `group_buy_notify_task` + MQ `topic.team_success` + 站内信表 `user_notify`**。纯 MQ（不做 HTTP 分支）；不复用 `alipay_notify_task`、不建参考项目那张通用 `notify_task`。
> 说明：本文是**参考代码（md）**，未改任何现有源码。

---

## 0. 最终决策记录（为什么这样做）

| 问题 | 决策 | 理由 |
|---|---|---|
| 成团通知走通用 `notify_task`？ | ❌ 不建 | 本地已有 `alipay_notify_task` 承担可靠投递账本定位，不需要第二张"通用回调表" |
| 复用 `alipay_notify_task`？ | ❌ 不复用 | 它是**单订单维度**（out_trade_no）；成团是**团队维度**（teamId+多成员），语义/字段对不上，且会被现有 `AlipayNotifyJob` 误当支付宝回调重放 |
| 需要账本保证不丢？ | ✅ 要 | 与 `alipay_notify_task` 同逻辑：成团通知算正式业务，MQ 消费失败要有兜底重扫 |
| 怎么通知用户 | ✅ 站内信 `user_notify` | 用户选择"本地站内信表"，消费端写站内信，用户查通知可见 |
| 消息通道 | ✅ 仅 MQ（去掉 HTTP） | 只做站内信，`notify_url` 分支去掉，`GroupBuyTradePort` 只实现 MQ |

---

## 1. 闭环链路

```
支付宝回调 → GroupBuyOrderFilter(GROUP_BUY) → GroupBuySettlementService.settlementGroupBuyOrder
  └─ groupBuyOrderRepository.settlementGroupBuyOrder(aggregate)
       ├─ 订单明细置 COMPLETE（status=1）
       ├─ team.complete_count + 1
       ├─ target - complete == 1（凑齐最后一人）
       │    ├─ team.status → 1（成团）              ✅ 当前已实现
       │    ├─ 插一条 group_buy_notify_task（notify_status=0）  ← 本次新增
       │    └─ return GroupBuyNotifyTaskEntity
       └─ 未凑齐 → return null（不建任务）
  └─ 返回非空 → 线程池异步 execNotifyJob(task)：GroupBuyTradePort → publish(topic.team_success, parameterJson)
       └─ 失败不阻塞，靠 GroupBuyNotifyJob 兜底补偿
┌──────────────────────────────────────────────────────────────┐
│ MQ: s_pay_mall_exchange → topic.team_success → s_pay_mall_queue_team_success │
└───────────────────────────────┬──────────────────────────────┘
TeamSuccessTopicListener 消费
  └─ 解析 parameterJson → teamId
  └─ queryUserIdListByTeamId(teamId) 查团内全部成员
  └─ 批量 insert user_notify（站内信，is_read=0）
兜底：GroupBuyNotifyJob（@Scheduled 每分钟）
  └─ 扫 group_buy_notify_task where notify_status in (0,2) → 重发 topic.team_success → 更新状态
```

**一句话**：`group_buy_notify_task` 是"不丢任务的账本"（维度 teamId），MQ 是投递通道，`user_notify` 是用户看到的最终结果，`GroupBuyNotifyJob` 保证漏发能重扫。

## 3. SQL（`data/sql/group_buy_notify.sql`）

```sql
-- 拼团成团回调任务表（可靠投递账本，维度 team_id）
CREATE TABLE `group_buy_notify_task` (
  `id`              bigint(20)  NOT NULL AUTO_INCREMENT COMMENT '自增ID',
  `team_id`         varchar(32) NOT NULL COMMENT '拼团队伍ID',
  `activity_id`     bigint(20)  NOT NULL DEFAULT 0 COMMENT '活动ID',
  `notify_mq`       varchar(64)  DEFAULT NULL COMMENT 'MQ路由key: topic.team_success',
  `notify_status`   int(11)     NOT NULL DEFAULT 0 COMMENT '0待发 1成功 2重试 3失败',
  `notify_count`    int(11)     NOT NULL DEFAULT 0 COMMENT '重试次数',
  `parameter_json`  varchar(1024) DEFAULT NULL COMMENT '参数对象 {"teamId","outTradeNoList"}',
  `create_time`     datetime    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`     datetime    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_team_id` (`team_id`),
  KEY `idx_status`  (`notify_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='拼团成团回调任务';

-- 站内信表（通知用户的最终落点）
CREATE TABLE `user_notify` (
  `id`          bigint(20)  NOT NULL AUTO_INCREMENT COMMENT '自增ID',
  `user_id`     varchar(32) NOT NULL COMMENT '接收用户',
  `team_id`     varchar(32) NOT NULL COMMENT '团队ID',
  `activity_id` bigint(20)  NOT NULL DEFAULT 0 COMMENT '活动ID',
  `notify_type` varchar(32) NOT NULL DEFAULT 'TEAM_SUCCESS' COMMENT '通知类型',
  `title`       varchar(64)  DEFAULT NULL COMMENT '标题',
  `content`     varchar(512) DEFAULT NULL COMMENT '内容',
  `is_read`     int(11)     NOT NULL DEFAULT 0 COMMENT '0未读 1已读',
  `create_time` datetime    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_team_type` (`user_id`,`team_id`,`notify_type`),  -- 防 MQ 重复消费
  KEY `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户站内信';
```

### 5.3 任务服务 `IGroupBuyNotifyTaskService` + 实现

包：`cn.bugstack.domain.groupbuy.service.task`

```java
public interface IGroupBuyNotifyTaskService {
    /** 扫未执行任务并回调；返回 成功/失败/重试 计数 */
    Map<String, Integer> execNotifyJob() throws Exception;
    /** 指定单条任务立即执行（结算后即时投递用） */
    Map<String, Integer> execNotifyJob(GroupBuyNotifyTaskEntity notifyTask) throws Exception;
}
```

```java
@Slf4j
@Service
public class GroupBuyNotifyTaskService implements IGroupBuyNotifyTaskService {

    @Resource
    private IGroupBuyNotifyTaskRepository groupBuyNotifyTaskRepository; // 或直接在 domain 加仓储
    @Resource
    private ITradePort port;

    @Override
    public Map<String, Integer> execNotifyJob() throws Exception {
        return exec(groupBuyNotifyTaskRepository.queryUnExecutedNotifyTaskList());
    }

    @Override
    public Map<String, Integer> execNotifyJob(GroupBuyNotifyTaskEntity task) throws Exception {
        return exec(Collections.singletonList(task));
    }

    private Map<String, Integer> exec(List<GroupBuyNotifyTaskEntity> list) throws Exception {
        int success = 0, error = 0, retry = 0;
        for (GroupBuyNotifyTaskEntity task : list) {
            String response = port.groupBuyNotify(task);
            if ("success".equals(response)) {
                if (1 == groupBuyNotifyTaskRepository.updateNotifyTaskStatusSuccess(task)) success++;
            } else if ("error".equals(response)) {
                if (task.getNotifyCount() != null && task.getNotifyCount() > 4) {
                    if (1 == groupBuyNotifyTaskRepository.updateNotifyTaskStatusError(task)) error++;
                } else {
                    if (1 == groupBuyNotifyTaskRepository.updateNotifyTaskStatusRetry(task)) retry++;
                }
            }
        }
        Map<String, Integer> result = new HashMap<>();
        result.put("waitCount", list.size());
        result.put("successCount", success);
        result.put("errorCount", error);
        result.put("retryCount", retry);
        return result;
    }
}
```

> 仓储归属：任务表仓储既可在 `domain.groupbuy.repository` 新接口 `IGroupBuyNotifyTaskRepository`（更贴领域），也可 `GroupBuyOrderRepository` 直接内聚。二选一，保持一处实现。

```java
@Slf4j
@Component
public class TeamSuccessTopicListener {

    @Resource
    private IGroupBuyOrderDao groupBuyOrderDao;      // queryUserIdListByTeamId
    @Resource
    private IUserNotifyRepository userNotifyRepository;

    @RabbitListener(
            bindings = @QueueBinding(
                    value = @Queue(value = "${spring.rabbitmq.config.producer.topic_team_success.queue}"),
                    exchange = @Exchange(value = "${spring.rabbitmq.config.producer.exchange}", type = ExchangeTypes.TOPIC),
                    key = "${spring.rabbitmq.config.producer.topic_team_success.routing_key}"
            )
    )
    public void listener(String message) {
        log.info("接收消息（组队成功）:{}", message);
        // parameterJson: {"teamId":"xxx","outTradeNoList":[".."]}
        JSONObject param = JSON.parseObject(message);
        String teamId = param.getString("teamId");

        List<String> userIdList = groupBuyOrderDao.queryUserIdListByTeamId(teamId);
        if (CollectionUtils.isEmpty(userIdList)) return;

        // 依赖 user_notify(uk_user_team_type) 唯一键防 MQ 重复消费
        List<UserNotifyEntity> notifyList = userIdList.stream()
                .map(userId -> UserNotifyEntity.builder()
                        .userId(userId)
                        .teamId(teamId)
                        .notifyType("TEAM_SUCCESS")
                        .title("拼团成功提醒")
                        .content("您参与的拼团已成团")
                        .isRead(0)
                        .build())
                .collect(Collectors.toList());

        userNotifyRepository.insertList(notifyList);
        log.info("组队成功站内信写入完成 teamId:{} 用户数:{}", teamId, notifyList.size());
    }
}
```

```java
@Resource
private IGroupBuyNotifyTaskDao groupBuyNotifyTaskDao;
// import cn.bugstack.domain.groupbuy.model.entity.GroupBuyNotifyTaskEntity;
// import cn.bugstack.infrastructure.dao.IGroupBuyNotifyTaskDao;
// import cn.bugstack.infrastructure.dao.po.groupbuy.GroupBuyNotifyTask;
```

```java
@Override
@Transactional(timeout = 500)
public GroupBuyNotifyTaskEntity settlementGroupBuyOrder(GroupBuyTeamSettlementAggregate aggregate) {
    GroupBuySettlementCommandEntity command = aggregate.getSettlementCommand();
    GroupBuyTeamEntity team = aggregate.getGroupBuyTeamEntity();

    // 1. 当前订单明细 置 complete
    int orderUpdated = groupBuyOrderDao.updateOrderStatus2Complete(
            command.getUserId(), command.getOutTradeNo());
    if (orderUpdated != 1) {
        throw new AppException(ResponseCode.E0005, "拼团订单结算更新失败");
    }

    // 2. 团队 complete_count + 1
    int completeUpdated = groupBuyTeamDao.updateAddCompleteCount(team.getTeamId());
    if (completeUpdated != 1) {
        throw new AppException(ResponseCode.E0005, "拼团团队完成人数更新失败");
    }

    // 3. 未凑齐 → 非成团，不建任务
    boolean complete = team.getTargetCount() - team.getCompleteCount() == 1;
    if (!complete) {
        return null;
    }

    // 4. 凑齐最后一人 → 团队置成团
    int statusUpdated = groupBuyTeamDao.updateStatus2Complete(team.getTeamId());
    if (statusUpdated != 1) {
        throw new AppException(ResponseCode.E0005, "拼团团队状态更新失败");
    }

    // 5. 查该团已成团订单单号，组装通知任务
    List<String> outTradeNoList = groupBuyOrderDao.queryCompleteOutTradeNoListByTeamId(team.getTeamId());
    String parameterJson = JSON.toJSONString(new HashMap<String, Object>() {{
        put("teamId", team.getTeamId());
        put("outTradeNoList", outTradeNoList);
    }});

    // 6. 先落账本（兜底 Job 扫的就是这张表）——顺序不能反
    groupBuyNotifyTaskDao.insert(GroupBuyNotifyTask.builder()
            .teamId(team.getTeamId())
            .activityId(team.getActivityId())
            .notifyMq("topic.team_success")
            .notifyStatus(0)     // 待发
            .notifyCount(0)
            .parameterJson(parameterJson)
            .build());

    // 7. 返回领域对象，交给 service 异步投递
    return GroupBuyNotifyTaskEntity.builder()
            .teamId(team.getTeamId())
            .activityId(team.getActivityId())
            .notifyType("MQ")
            .notifyMQ("topic.team_success")
            .notifyCount(0)
            .notifyStatus(0)
            .parameterJson(parameterJson)
            .uuid(team.getTeamId() + "_trade_settlement_" + command.getOutTradeNo())
            .build();
}
```

> **顺序关键**：先 insert 账本再异步发 MQ。即使 MQ 发送失败，`GroupBuyNotifyJob` 也能扫到 `notify_status in (0,2)` 重发，不丢。

```java
        } catch (Exception e) {
            log.error("成团通知即时投递失败，交由兜底Job补偿 teamId:{}", notifyTask.getTeamId(), e);
        }
    });
}
```
> 需在 service 注入 `IGroupBuyNotifyTaskService groupBuyNotifyTaskService` 和现有线程池 `ThreadPoolExecutor`。

## 9. 幂等 / 边界注意

1. **任务幂等**：结算触发点唯一（只凑齐最后一人返回非空），insert 前无需查重；兜底更新用 `where team_id and notify_status=0` 保证只成功一次。
2. **站内信防重**：MQ 是 at-least-once（重复消费），`user_notify` 用唯一键 `(user_id, team_id, notify_type)` + `insertList` 批量插入即可挡重，不必在消费端加锁。
3. **多实例**：`GroupBuyNotifyJob` 建议 Redisson `tryLock`；本机单实例先不加。
4. **只走 MQ、不走 HTTP**：`GroupBuyTradePort` 已去掉 HTTP 分支；`GroupBuyNotifyTaskEntity.notifyUrl` 保留但不用。
5. **`notify_count > 4` 判失败**：重试上限与 `alipay_notify_task` 语义一致（参考项目为 4），可按需调。
