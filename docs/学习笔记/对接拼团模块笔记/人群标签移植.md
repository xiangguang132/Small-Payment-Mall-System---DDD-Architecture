# 人群标签移植

> 目标项目：`s-pay-mall-ddd-cc`
> 参考项目：`D:\code\group-buy-market`
> 本文用途：说明“人群标签过滤”是什么、参考项目如何实现，以及如何把该能力完整移植到当前项目。

## 1. 人群标签过滤是什么

人群标签过滤不是简单地在 SQL 中按 `tag_id` 过滤商品，而是用 `tagId` 定义一个“人群包”，运行时判断当前 `userId` 是否命中该人群包，再决定两类业务结果：

1. 活动层：用户能否看到该拼团活动、能否参与该拼团。
2. 优惠层：用户能否享受该拼团专属的 TAG 人群优惠。

核心数据链路如下：

```text
crowd_tags            人群标签元信息，保存 tagId、名称、统计量
crowd_tags_detail     人群标签明细，保存 tagId + userId
crowd_tags_job        人群标签计算任务，保存规则和统计时间范围

group_buy_activity.tag_id      活动限制对应的人群包
group_buy_activity.tag_scope   限制范围：1 可见限制、2 参与限制
group_buy_discount.tag_id      专属优惠对应的人群包
```

运行期不直接查询明细表，而是把人群包写入 Redis BitSet，通过 `tagId` 作为 key、`userId` 的稳定 hash 作为 bit index 做 O(1) 命中判断。

## 2. 参考项目完整链路

参考项目 `group-buy-market` 的人群标签链路已经完整接通：

```text
TagService.execTagBatchJob
  -> 查询 crowd_tags_job
  -> 生成符合规则的用户列表
  -> 写入 crowd_tags_detail
  -> 写入 Redis RBitSet[tagId]
  -> 更新 crowd_tags.statistics

拼团试算
  -> MarketNode 加载活动、折扣、商品
  -> AbstractDiscountCalculateService
       discountType = TAG 时先判断 isTagCrowdRange
       不命中返回原价，不执行专属优惠
  -> TagNode
       tagId 为空：visible = true, enable = true
       tagId 非空：先判断人群，再按 tagScope 决定 visible/enable
  -> EndNode 返回试算结果
  -> 锁单入口拦截 !visible || !enable，返回 E0007
```

## 3. 数据设计

建议在 `s-pay-mall-ddd-cc` 中使用与参考项目一致的三张表：

| 表 | 作用 | 核心字段 |
| --- | --- | --- |
| `crowd_tags` | 人群包元信息 | `tag_id`、`tag_name`、`statistics` |
| `crowd_tags_detail` | 人群包用户明细 | `tag_id`、`user_id`，唯一键 `(tag_id, user_id)` |
| `crowd_tags_job` | 人群计算任务 | `tag_id`、`batch_id`、`tag_type`、`tag_rule`、统计时间范围、状态 |

可参考以下 DDL：

```sql
CREATE TABLE IF NOT EXISTS `crowd_tags` (
    `id`          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `tag_id`      VARCHAR(32)  NOT NULL COMMENT '人群标签ID',
    `tag_name`    VARCHAR(64)  NOT NULL COMMENT '人群名称',
    `tag_desc`    VARCHAR(256) NOT NULL DEFAULT '' COMMENT '人群描述',
    `statistics`  INT          NOT NULL DEFAULT 0 COMMENT '人群标签统计量',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_tag_id` (`tag_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '人群标签表';

CREATE TABLE IF NOT EXISTS `crowd_tags_detail` (
    `id`          INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `tag_id`      VARCHAR(32)  NOT NULL COMMENT '人群标签ID',
    `user_id`     VARCHAR(64)  NOT NULL COMMENT '用户ID',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_tag_user` (`tag_id`, `user_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '人群标签明细表';

CREATE TABLE IF NOT EXISTS `crowd_tags_job` (
    `id`              INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `tag_id`          VARCHAR(32)  NOT NULL COMMENT '人群标签ID',
    `batch_id`        VARCHAR(32)  NOT NULL COMMENT '批次ID',
    `tag_type`        TINYINT      NOT NULL DEFAULT 0 COMMENT '标签类型；0参与量、1消费金额',
    `tag_rule`        VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '标签规则',
    `stat_start_time` DATETIME     NOT NULL COMMENT '统计开始时间',
    `stat_end_time`   DATETIME     NOT NULL COMMENT '统计结束时间',
    `status`          TINYINT      NOT NULL DEFAULT 0 COMMENT '状态；0初始、1计划、2重置、3完成',
    `create_time`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_batch_id` (`batch_id`),
    KEY `idx_tag_status` (`tag_id`, `status`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '人群标签计算任务表';
```

## 6. 核心实现建议

### 6.1 标签任务服务

```java
public interface ITagService {
    void execTagBatchJob(String tagId, String batchId);
}
```

```java
public class TagService implements ITagService {

    private ITagRepository repository;

    @Override
    public void execTagBatchJob(String tagId, String batchId) {
        CrowdTagsJobEntity job = repository.queryCrowdTagsJobEntity(tagId, batchId);
        // TODO 真正根据 tagType、tagRule、统计时间范围采集用户
        List<String> userIdList = loadUserIdList(job);
        for (String userId : userIdList) {
            repository.addCrowdTagsUserId(tagId, userId);
        }
        repository.updateCrowdTagsStatistics(tagId, userIdList.size());
    }
}
```

### 6.2 明细落库与 BitSet

```java
public void addCrowdTagsUserId(String tagId, String userId) {
    try {
        crowdTagsDetailDao.addCrowdTagsUserId(detail(tagId, userId));
    } catch (DuplicateKeyException ignored) {
        // 明细已存在时不重复插入，但 BitSet 必须保证置位
    }
    RBitSet bitSet = redisService.getBitSet(tagId);
    bitSet.set(redisService.getIndexFromUserId(userId), true);
}
```

### 6.3 运行期人群命中

```java
public boolean withinTagCrowdRange(String tagId, String userId) {
    if (StringUtils.isBlank(tagId)) {
        return true;
    }
    RBitSet bitSet = redisService.getBitSet(tagId);
    if (!bitSet.isExists()) {
        // 人群包不存在时默认放行，避免配置未生效导致业务不可用
        return true;
    }
    return bitSet.get(redisService.getIndexFromUserId(userId));
}
```

### 6.4 TagNode 按 tagScope 过滤

建议不要照抄参考项目按数组下标解析，而是按值判断：

```java
private boolean visibleAllowed(String tagScope) {
    if (StringUtils.isBlank(tagScope)) return true;
    return !Arrays.asList(tagScope.split(",")).contains("1");
}

private boolean enableAllowed(String tagScope) {
    if (StringUtils.isBlank(tagScope)) return true;
    return !Arrays.asList(tagScope.split(",")).contains("2");
}
```

`TagNode` 主逻辑：

```java
String tagId = activity.getTagId();
if (StringUtils.isBlank(tagId)) {
    dynamicContext.setVisible(true);
    dynamicContext.setEnable(true);
    return router(request, dynamicContext);
}

boolean within = repository.withinTagCrowdRange(tagId, request.getUserId());
boolean visible = visibleAllowed(activity.getTagScope());
boolean enable = enableAllowed(activity.getTagScope());

dynamicContext.setVisible(visible || within);
dynamicContext.setEnable(enable || within);
return router(request, dynamicContext);
```

含义：

- `tagScope = 1`：只有命中人群的用户可见
- `tagScope = 2`：只有命中人群的用户可参与
- `tagScope = 1,2`：可见和参与都限制
- `tagScope` 为空：默认全部可见、可参与

## 8. 验证方式

1. 跑一次人群标签任务，写入测试用户。
2. 直接检查 Redis BitSet：命中用户返回 true，未命中用户返回 false。
3. 跑拼团试算：
   - 命中用户：`visible = true`、`enable = true`
   - 未命中用户：根据 `tagScope` 返回 false
4. 跑 TAG 折扣试算：
   - 命中用户：享受折扣价
   - 未命中用户：返回原价
5. 后续有锁单入口后，验证未命中用户被 E0007 拦截。

## 9. 注意事项

- 参考项目的 `TagService` 目前硬编码用户列表，“采集用户信息”仍是 TODO，不能作为生产级人群计算实现。
- `crowd_tags.statistics` 参考项目使用 `statistics + #{statistics}`，重复跑任务会累加失真；建议直接回写本次明细数或按明细表幂等统计。
- 明细表唯一键 `(tag_id, user_id)` 存在时，插入会抛 `DuplicateKeyException`，但 BitSet 置位必须在异常处理后仍然执行。
- 人群包不存在时建议默认放行，避免运营配置缺失导致整个活动不可见。
- `tag_scope` 建议按逗号拆分后判断是否包含 `1`、`2`，不要依赖固定顺序。
- `group_buy_activity.tag_id` 和 `group_buy_discount.tag_id` 都指向 `crowd_tags.tag_id`，但二者职责不同：前者控制活动可见/参与，后者控制专属优惠。
- 当前项目的 `DiscountTypeEnum` 使用 `Integer code`，判断 TAG 时应使用 `DiscountTypeEnum.TAG.getCode().equals(groupBuyDiscount.getDiscountType())`。
