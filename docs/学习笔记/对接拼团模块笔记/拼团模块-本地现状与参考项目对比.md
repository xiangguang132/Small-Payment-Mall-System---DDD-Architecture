# 拼团模块 — 本地现状与参考项目对比

> 调研日期：2026-08-21
> 参考项目：`E:\group-buy-market`（小傅哥 spay-mall 拼团完整实现）
> 本地项目：`D:\code\s-pay-mall-ddd-cc`（已完成普通下单订单流程，拼团进行中）

## 0. 一句话结论

本地拼团 **domain 层（试算/折扣/锁单/结算）+ 设计模式框架 + 基础设施 DAO/PO/Mapper + 支付回调结算接线** 已基本完成，约 20 个领域测试通过；
真正缺的是 **trigger 接口暴露、数据库表数据、团队库存占用、退单逆向、成团通知** 这一层"贯通业务代码"。
**设计模式模板不缺**——参考项目靠外部依赖 `xfg-wrench-starter-design-framework`，本地已手抄进 `cn.bugstack.types.design.framework` 且拼团已在用。

## 4. 本地未完成清单（按依赖顺序）

1. **数据库表与种子数据**：无 `group_buy_activity`/`group_buy_discount` 建表 SQL 与数据 → MarketNode 实际运行必抛 `NOT_FOUND`，链路无法跑通。
   - 参考：`docs/dev-ops/mysql/sql/2-29-group_buy_market.sql`
2. **trigger 接口暴露**：`trigger/http/GroupBuyController` 是空壳 `{}`，试算/锁单/结算/进度全部无 HTTP 入口。
   - 参考：`MarketTradeController`（`lockMarketPayOrder`/`settlementMarketPayOrder`/`refundMarketPayOrder`）+ `MarketIndexController`
3. **拼团锁单接入支付**：现成普通下单是 `lock_order → confirm_order`（`order_lock` 表）两阶段；拼团锁单后如何创建 `pay_order` 发起支付宝支付尚未接线。
4. **团队库存占用**：锁单规则链缺 `TeamStockOccupyRuleFilter`（Redis `INCR` 抢占名额，参考用 `setNx` 兜底）。
5. **退单/逆向**：基础退单链路已补齐；剩余缺口是退款后库存恢复、MQ 通知、退款结果仓储闭环。
6. **成团通知**：缺 `notify_task` 成团本地消息表、MQ `topic.team_success`、`TradePort` 分布式锁、`GroupBuyNotifyJob` 兜底定时扫。
7. **人群标签占位**：`withinTagCrowdRange()` 需从 `return false` 换成真实 CrowdTags BitSet 判定（本地已有 `domain.crowdtags` 人群标签实现可复用）。

## 5. 设计模式模板 vs 业务代码：先做哪个

**不需要先补设计模式模板。** 本地 `types/design/framework` 的责任链与策略树是完整实现（`LinkedList` 160 行等），拼团 domain 已在 import 使用，不存在"模板缺了导致拼团写不下去"的情况。

**下一步补业务贯通层**，最小闭环：① 建表 SQL + 种子数据 → ② 补 `GroupBuyController`（试算+锁单+进度，锁单复用现成支付宝下单）→ ③ 回调结算点已有（GroupBuyOrderFilter），跑通"试算→锁单→支付→回调结算"后，再回头补团队库存、退单、成团通知。

## 6. 参考项目可抄的关键手法（供补代码时对照）

- 并发幂等三板斧：明细 `biz_id`（本地为 `out_trade_no`）唯一索引防重 + `lock_count < target_count` 条件更新防超卖 + Redis `INCR` 组队库存。
- 折扣值存 `market_expr` 字符串（`20`/`100,10`/`0.9`/`10`），非 JSON；`group_buy_discount` 是关系型字段。
- 结算凑齐判断：`target_count - complete_count == 1` 且更新成功（条件更新）才置 team 成团。
- 退单策略由 `RefundTypeEnumVO.getRefundStrategy(组队状态, 订单状态)` 选路，3 种形态聚合 `GroupBuyRefundAggregate`。
