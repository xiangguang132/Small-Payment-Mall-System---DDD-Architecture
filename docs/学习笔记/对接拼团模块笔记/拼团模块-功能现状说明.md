# 拼团模块 — 功能现状说明

> 整理日期：2026-08-23
> 说明对象：`D:\code\s-pay-mall-ddd-cc`（本地）
> 结论速览：**拼团还没有整体走通**。领域层 + 支付回调结算基本完成，但 trigger 接口、库表数据、团队库存占用、成团通知仍未补全，端到端还跑不起来。

## 0. 一句话结论

本地拼团 **domain 层（试算/折扣/锁单/结算）+ 设计模式框架 + 基础设施 DAO/PO/Mapper + 支付回调结算接线** 已基本完成（约 20 个领域测试通过）；
真正缺的是 **trigger 接口暴露、数据库表数据、团队库存占用、退单逆向、成团通知** 这一层"贯通业务代码"。

**最直接的堵点：** `GroupBuyController` 已有试算/锁单等入口，活动/折扣种子数据已入库；下一步是把锁单接入支付、补团队库存占用和成团通知。

## 3. 未完成清单（按依赖顺序）

1. **拼团锁单接入支付**：现成普通下单是 `lock_order → confirm_order`（`order_lock` 表）两阶段；拼团锁单后如何创建 `pay_order` 发起支付宝支付尚未接线。当前 `OrderService.createOrder` 固定写死 `OrderTypeEnum.DIRECT`，无 `GROUP_BUY` 的 pay_order 生成路径。
2. **团队库存占用**：锁单规则链缺 `TeamStockOccupyRuleFilter`（Redis `INCR` 抢占名额，参考用 `setNx` 兜底）。
3. **成团通知**：缺 `notify_task` 成团本地消息表、MQ `topic.team_success`、`TradePort` 分布式锁、`GroupBuyNotifyJob` 兜底定时扫。
4. **人群标签占位**：`withinTagCrowdRange()` 需从 `return false` 换成真实 CrowdTags BitSet 判定（本地已有 `domain.crowdtags` 人群标签实现可复用）。
