## 0. 一句话结论

本地拼团 **domain 层（试算/折扣/锁单/结算）+ 设计模式框架 + 基础设施 DAO/PO/Mapper + 支付回调结算接线** 已基本完成（约 20 个领域测试通过）；
真正缺的是 **trigger 接口暴露、数据库表数据、团队库存占用、退单逆向、成团通知** 这一层"贯通业务代码"。

**最直接的堵点：** `GroupBuyController` 是空壳类，外部无任何 HTTP 入口；且库表无活动/折扣数据，试算一跑就抛 `NOT_FOUND`。

## 3. 未完成清单（按依赖顺序）

1. **数据库表与种子数据**：无 `group_buy_activity` / `group_buy_discount` 建表 SQL 与数据 → `MarketNode` 实际运行必抛 `NOT_FOUND`，链路无法跑通。
   - 参考：`docs/dev-ops/mysql/sql/2-29-group_buy_market.sql`
2. **trigger 接口暴露**：`trigger/http/GroupBuyController` 是空壳 `{}`，试算/锁单/结算/进度全部无 HTTP 入口。
3. **拼团锁单接入支付**：现成普通下单是 `lock_order → confirm_order`（`order_lock` 表）两阶段；拼团锁单后如何创建 `pay_order` 发起支付宝支付尚未接线。当前 `OrderService.createOrder` 固定写死 `OrderTypeEnum.DIRECT`，无 `GROUP_BUY` 的 pay_order 生成路径。
4. **团队库存占用**：锁单规则链缺 `TeamStockOccupyRuleFilter`（Redis `INCR` 抢占名额，参考用 `setNx` 兜底）。
5. **退单/逆向**：基础退单链路已补齐（`GroupBuyRefundOrderService` + 3 策略 + `TimeoutOrderJob` + `GroupBuyRefundTimeoutTaskProvider`）；剩余缺口是退款后库存恢复、MQ 通知、退款结果仓储闭环。
6. **成团通知**：缺 `notify_task` 成团本地消息表、MQ `topic.team_success`、`TradePort` 分布式锁、`GroupBuyNotifyJob` 兜底定时扫。
7. **人群标签占位**：`withinTagCrowdRange()` 需从 `return false` 换成真实 CrowdTags BitSet 判定（本地已有 `domain.crowdtags` 人群标签实现可复用）。

## 6. 建议的下一步

**不需要先补设计模式模板** —— 本地 `types/design/framework` 是完整实现，无阻塞。

**最小闭环（按依赖顺序）：**
1. 建表 SQL + 种子数据（`group_buy_activity` / `group_buy_discount`）→ 试算链路别再抛 `NOT_FOUND`
2. 补 `GroupBuyController`（试算 + 锁单 + 进度）
3. 拼团锁单接入支付：生成 `GROUP_BUY` 的 pay_order 走支付宝
4. 跑通「试算 → 锁单 → 支付 → 回调结算」后，再回头补团队库存占用、退单逆向、成团通知
