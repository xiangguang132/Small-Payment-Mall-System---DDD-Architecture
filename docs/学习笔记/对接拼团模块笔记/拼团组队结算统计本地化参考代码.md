# 拼团组队结算统计本地化参考代码（CC）

> 适用项目：`D:\code\s-pay-mall-ddd-cc`
> 参考项目：`D:\code\group-buy-market`
> 本文只做参考，不直接修改业务代码。

## 1. 结论

当前 CC 已经具备：

- 支付宝支付能力：`AliPayController`、`OrderService`、`pay_order`。
- 拼团试算能力：`groupbuy/service/trial`。
- 拼团锁单规则链：`groupbuy/service/rule` + `multilink`。
- 拼团团队/参团订单基础表：`group_buy_team`、`group_buy_order`。

当前还缺：

- `group_buy_order` 支付成功后没有状态更新。
- `group_buy_team.complete_count` 没有结算累加。
- `group_buy_team.status` 没有成团更新。
- `pay_order` 没有 `orderType/activityId/teamId` 等拼团字段。
- 支付宝回调没有 `GROUP_BUY` 分支。
- 没有团队进度/结算统计查询。
- 没有成团回调任务（可按需后补）。

参考项目里的“拼团组队结算统计”不是独立报表服务，而是由三块组成：

1. 团队进度统计：`queryGroupBuyProgress` 返回 `targetCount/completeCount/lockCount`。
2. 支付结算：支付回调后更新参团订单状态，累加 `completeCount`，达到目标后更新团队状态。
3. 成团回调：可选写入 `notify_task`，保存 `teamId + outTradeNoList` 快照。

## 2. 本地化目标链路

```text
拼团试算
  -> 拼团锁单规则链
  -> 创建 group_buy_team / group_buy_order
  -> 创建 pay_order，保存 orderType=GROUP_BUY
  -> 支付宝支付
  -> pay_notify 回调
     -> 查询 pay_order 判断 orderType
     -> GROUP_BUY 走拼团结算规则链
     -> 更新 group_buy_order.status
     -> 更新 group_buy_team.complete_count
     -> 达到 target_count 后更新 team.status=1
     -> 更新 pay_order 为 PAY_SUCCESS
  -> 查询团队进度/统计
```

不需要新建一套支付系统，只需复用现有 `pay_order`、支付宝验签、支付单状态机。

## 3. 与参考项目的模型差异

| 参考项目 | CC 现状 | 本地化要求 |
| --- | --- | --- |
| `group_buy_order` 一个团队一行 | `group_buy_team` 一个团队一行 | 不能照搬参考 SQL |
| `group_buy_order_list` 用户参团订单 | `group_buy_order` 用户参团订单 | 结算更新写 `group_buy_order` |
| `TradeSettlementOrderService` | 新增 `GroupBuySettlementService` | 使用 CC 的 `groupbuy` 包 |
| `muti_model` 责任链 | CC `design/framework/link/multilink` | 复用现有 `multilink` |
| `Date` | `LocalDateTime` | 使用 CC 时间类型 |
| `TradeSettlementRuleFilterBackEntity` | 新增 CC 结算反馈实体 | 字段按 CC 实体写 |
| 独立 `MarketTradeController` 支付入口 | 现有 `pay_order` + 支付宝回调 | 接入现有支付入口 |

## 4. 数据表变更建议

### 4.1 `pay_order`

```sql
ALTER TABLE `pay_order`
    ADD COLUMN `order_type` VARCHAR(16) NOT NULL DEFAULT 'DIRECT' COMMENT '订单类型；DIRECT普通购买、GROUP_BUY拼团',
    ADD COLUMN `activity_id` BIGINT NULL COMMENT '拼团活动ID',
    ADD COLUMN `team_id` VARCHAR(32) NULL COMMENT '拼团团队ID',
    ADD COLUMN `original_amount` DECIMAL(8, 2) NULL COMMENT '商品原价',
    ADD COLUMN `deduction_amount` DECIMAL(8, 2) NULL COMMENT '优惠金额';
```

说明：

- 普通购买保持 `DIRECT`，不破坏现有链路。
- 拼团创建 `pay_order` 时写入 `GROUP_BUY`、`activityId`、`teamId`。
- 支付时间建议继续使用现有 `pay_time`，或按支付宝 `gmt_payment` 单独落库。

### 4.2 `group_buy_order`

当前 `biz_id` 保存的是 `outTradeNo`，所以可以先按 `biz_id` 结算查询。

```sql
ALTER TABLE `group_buy_order`
    ADD COLUMN `pay_time` DATETIME NULL COMMENT '支付成功时间';
```

### 4.3 `notify_task`（可选）

如果后续要做成团回调，可以补：

```sql

```

import cn.bugstack.types.enums.ResponseCode;

import org.springframework.stereotype.Service;

import java.time.LocalDateTime;

@Service
public class SettableRuleFilter implements ILogicHandler<
        GroupBuySettlementCommandEntity,
        GroupBuySettlementRuleFilterFactory.DynamicContext,
        GroupBuySettlementFeedBackEntity> {

    @Resource
    private IGroupBuyRepository groupBuyRepository;

    @Override
    public GroupBuySettlementFeedBackEntity apply(
            GroupBuySettlementCommandEntity requestParameter,
            GroupBuySettlementRuleFilterFactory.DynamicContext dynamicContext) {
        GroupBuyOrderEntity order = dynamicContext.getGroupBuyOrderEntity();
        GroupBuyTeamEntity team = groupBuyRepository.queryGroupBuyTeamByTeamId(order.getTeamId());
        if (team == null) {
            throw new AppException(ResponseCode.E0005, "拼团团队不存在");
        }

        LocalDateTime payTime = requestParameter.getPayTime();
        if (payTime != null
                && team.getValidEndTime() != null
                && !payTime.isBefore(team.getValidEndTime())) {
            throw new AppException(ResponseCode.E0106);
        }

        dynamicContext.setGroupBuyTeamEntity(team);
        return next(requestParameter, dynamicContext);
    }

}

### 6.11 结算服务实现

```java
package cn.bugstack.domain.groupbuy.service.settlement;

import cn.bugstack.domain.groupbuy.model.aggregate.GroupBuyTeamSettlementAggregate;
import cn.bugstack.domain.groupbuy.model.entity.GroupBuySettlementCommandEntity;
import cn.bugstack.domain.groupbuy.model.entity.GroupBuySettlementFeedBackEntity;
import cn.bugstack.domain.groupbuy.model.entity.GroupBuyTeamEntity;
import cn.bugstack.domain.groupbuy.model.valobj.GroupBuyProgressVO;
import cn.bugstack.domain.groupbuy.repository.IGroupBuyRepository;
import cn.bugstack.domain.groupbuy.service.settlement.factory.GroupBuySettlementRuleFilterFactory;
import cn.bugstack.types.design.framework.link.multilink.chain.BusinessLinkedList;
import cn.bugstack.types.enums.ResponseCode;
import cn.bugstack.types.exception.AppException;
import org.springframework.stereotype.Service;

import javax.annotation.Resource;

@Service
public class GroupBuySettlementService implements IGroupBuySettlementService {

    @Resource(name = "groupBuySettlementRuleFilter")
    private BusinessLinkedList<GroupBuySettlementCommandEntity,
            GroupBuySettlementRuleFilterFactory.DynamicContext,
            GroupBuySettlementFeedBackEntity> groupBuySettlementRuleFilter;

    @Resource
    private IGroupBuyRepository groupBuyRepository;

    @Override
    public GroupBuySettlementFeedBackEntity settlementGroupBuyOrder(
            GroupBuySettlementCommandEntity command) throws Exception {
        GroupBuySettlementFeedBackEntity feedBack = groupBuySettlementRuleFilter.apply(
                command,
                new GroupBuySettlementRuleFilterFactory.DynamicContext()
        );
        if (feedBack == null) {
            throw new AppException(ResponseCode.UN_ERROR, "拼团组队结算规则链未返回结果");
        }

        GroupBuyTeamEntity team = GroupBuyTeamEntity.builder()
                .teamId(feedBack.getTeamId())
                .activityId(feedBack.getActivityId())
                .targetCount(feedBack.getTargetCount())
                .completeCount(feedBack.getCompleteCount())
                .lockCount(feedBack.getLockCount())
                .status(feedBack.getStatus())
                .validStartTime(feedBack.getValidStartTime())
                .validEndTime(feedBack.getValidEndTime())
                .notifyUrl(feedBack.getNotifyUrl())
                .build();

        GroupBuyTeamSettlementAggregate aggregate = GroupBuyTeamSettlementAggregate.builder()
                .settlementCommand(command)
                .groupBuyTeamEntity(team)
                .build();

        boolean complete = groupBuyRepository.settlementGroupBuyOrder(aggregate);
        feedBack.setComplete(complete);
        return feedBack;
    }

    @Override
    public GroupBuyProgressVO queryGroupBuyProgress(String teamId) {
        return groupBuyRepository.queryGroupBuyProgress(teamId);
    }

}

            .status(team.getStatus())
            .validEndTime(team.getValidEndTime())
            .build();
}

@Override
@Transactional(timeout = 500)
public boolean settlementGroupBuyOrder(GroupBuyTeamSettlementAggregate aggregate) {
    GroupBuySettlementCommandEntity command = aggregate.getSettlementCommand();
    GroupBuyTeamEntity team = aggregate.getGroupBuyTeamEntity();

    int orderUpdated = groupBuyOrderDao.updateOrderStatus2Complete(
            command.getUserId(),
            command.getOutTradeNo(),
            command.getPayTime()
    );
    if (orderUpdated != 1) {
        throw new AppException(ResponseCode.E0005, "拼团订单结算更新失败");
    }

    int completeUpdated = groupBuyTeamDao.updateAddCompleteCount(team.getTeamId());
    if (completeUpdated != 1) {
        throw new AppException(ResponseCode.E0005, "拼团团队完成人数更新失败");
    }

    boolean complete = team.getTargetCount() - team.getCompleteCount() == 1;
    if (complete) {
        int statusUpdated = groupBuyTeamDao.updateStatus2Complete(team.getTeamId());
        if (statusUpdated != 1) {
            throw new AppException(ResponseCode.E0005, "拼团团队状态更新失败");
        }
    }

    return complete;
}
```

说明：

- `team.getCompleteCount()` 是结算前从规则链查出的完成人数。
- 如果 `targetCount - completeCount == 1`，说明本次支付是最后一人。
- 事务放在 `GroupBuyRepository`，和现有 `lockGroupBuyOrder` 风格一致。

```java
@RequestMapping(value = "pay_notify", method = RequestMethod.POST)
public String payNotify(HttpServletRequest request) {
    try {
        if ("TRADE_SUCCESS".equals(request.getParameter("trade_status"))) {
            Map<String, String> params = collectAlipayParams(request);
            boolean checkSignature = checkAlipaySignature(request, params);
            if (!checkSignature) {
                return "false";
            }

            String outTradeNo = params.get("out_trade_no");
            PayOrderEntity payOrder = orderService.queryPayOrderByOrderId(outTradeNo);
            if (payOrder == null) {
                throw new AppException(ResponseCode.E0104);
            }

            if ("GROUP_BUY".equals(payOrder.getOrderType())) {
                LocalDateTime payTime = parseAlipayTime(params.get("gmt_payment"));
                groupBuySettlementService.settlementGroupBuyOrder(
                        GroupBuySettlementCommandEntity.builder()
                                .userId(payOrder.getUserId())
                                .outTradeNo(outTradeNo)
                                .payTime(payTime)
                                .build()
                );
            }

            orderService.changeOrderPaySuccess(outTradeNo);
        }
        return "success";
    } catch (Exception e) {
        log.error("支付回调，处理失败", e);
        return "false";
    }
}
```

说明：

- 普通购买仍走 `changeOrderPaySuccess`。
- 拼团先结算，再更新 `pay_order` 为支付成功。
- `gmt_payment` 需要按支付宝返回格式解析，建议用 `DateTimeFormatter`。

## 8. 幂等与并发注意事项

- 重复支付回调不能重复累加 `complete_count`，`updateAddCompleteCount` 必须有 `complete_count < target_count`。
- `updateOrderStatus2Complete` 必须带 `status = 0`，让同一订单只能结算一次。
- 如果重复回调时订单已经 `status = 1`，建议直接返回已完成结果，不要继续抛业务异常。
- 结算规则链的 `DynamicContext` 每次请求新建，不能复用。
- 结算事务和现有 `lockGroupBuyOrder` 一样放在 Repository 层，保持当前代码风格。
- 如果要做成团回调，`notify_task` 写入应在成团事务内完成，回调发送不要阻塞支付回调主流程。

## 10. 本地化原则

1. 不要照搬参考项目的 `TradeRepository.settlementMarketPayOrder()`，因为 CC 的团队表是 `group_buy_team`。
2. 不要新开一套支付入口，复用 `AliPayController`、`pay_order`、`TimeoutCloseOrderJob`。
3. 结算规则链可以复用现有 `multilink`，不需要再复制一套责任链框架。
4. 当前 `group_buy_order.biz_id` 已作为 `outTradeNo` 使用；如果后续拆字段，记得同步改 Mapper。
5. “统计”如果是活动级汇总，而不是团队级进度，参考项目也没有现成实现，需要重新设计查询或统计表。
