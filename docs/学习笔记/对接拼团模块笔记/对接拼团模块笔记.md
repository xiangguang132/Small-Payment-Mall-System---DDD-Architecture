# 对接拼团模块笔记

## 总体结论

- 不采用两个项目 HTTP 对接，而是把 `group-buy-market` 的拼团逻辑重写到 `s-pay-mall-ddd-cc`。
- 拼团作为 CC 内的 `groupbuy` 领域模块。
- 商品使用 CC 现有 `product`，不引入原项目的 `sku`。
- `pay_order` 通过 `order_type` 区分 `DIRECT` 和 `GROUP_BUY`。
- 普通购买链路保持不变。

## 目标表结构

```text
group_buy_activity      拼团活动配置/模板
group_buy_discount      优惠方案
group_buy_team          实际拼团团队
group_buy_order         用户参团订单
pay_order               支付单
notify_task             成团回调任务
crowd_tags              人群标签
crowd_tags_detail       人群标签明细
crowd_tags_job          人群标签计算任务
```

当前按“一个拼团订单只买一个商品”设计，暂不建 `group_buy_order_detail`。以后一单多商品时再补。

## 旧表映射

```text
旧 group_buy_order      -> 新 group_buy_team
旧 group_buy_order_list -> 新 group_buy_order
旧 sku                  -> CC product
旧 sc_sku_activity      -> group_buy_activity.product_id
旧支付部分              -> pay_order
```

## 推荐开发顺序

```text
1. 拼团配置 PO / DAO / Mapper
2. 试算 Domain Service
3. 优惠计算
4. 人群标签
5. 锁单 / 创建拼团订单
6. 支付回调 / 拼团结算
7. 成团回调任务
8. 超时关单
```

不建议一开始写完整活动配置 CRUD。试算只依赖查询，增删改可以后补。

## 注意事项

- `discount_id` 是 `varchar(16)`，Java 字段必须是 `String`，不能是 `Integer`。
- Domain 包统一使用 `cn.bugstack.domain.groupbuy`。
- Mapper XML 的 namespace 必须和 DAO 全限定名一致。
- PO 时间类型建议统一，例如 `LocalDateTime`。
- 建表 SQL 参考：`D:\code\group-buy-market\docs\sql\2026-08-11-group-buy-target-ddl.sql`
