# 订单下单链路与启动报错分析

## 1. 报错现象

启动时出现下面的异常：

```text
Parameter 0 of constructor in cn.bugstack.domain.order.model.service.OrderService required a bean of type 'cn.bugstack.domain.order.adapter.repository.IOrderRepository' that could not be found.
```

这表示 `OrderService` 构造方法需要注入 `IOrderRepository`，但 Spring 容器里没有找到这个接口对应的实现 Bean。

## 2. 根因

问题不在 `OrderService` 本身，而在仓储实现没有被 Spring 扫描成 Bean。

当前工程里：

- `OrderService` 使用了 `@Service`
- `OrderRepository` 实现了 `IOrderRepository`
- 但 `OrderRepository` 没有 `@Repository` 或 `@Component`

所以 Spring 只能识别到服务层，识别不到仓储实现，最终导致构造器注入失败。

## 3. 和参考项目的差异

参考项目 `D:\code\s-pay-mall-ddd` 中，`OrderRepository` 是这样注册的：

- `@Repository` 标记仓储实现
- Spring 扫描到 `cn.bugstack.infrastructure.adapter.repository.OrderRepository`
- 进而可以把它注入到 `OrderService`

当前工程的修复就是补上同样的注解。

## 4. 已修复内容

已在以下文件中添加 `@Repository`：

- `../../../s-pay-mall-ddd-infrastructure/src/main/java/cn/bugstack/infrastructure/adapter/repository/OrderRepository.java`

这样 Spring 启动时就能创建 `OrderRepository` Bean，`IOrderRepository` 的依赖注入会恢复正常。

## 5. 订单下单逻辑梳理

订单下单的核心入口是接口层：

1. 前端请求进入 `AliPayController.createPayOrder`
2. 控制器把 `userId` 和 `productId` 封装成 `ShopCartEntity`
3. 调用 `IOrderService.createOrder`
4. `OrderService` 进入领域层，先检查是否已有未支付订单
5. 如果存在未支付订单，直接返回原支付链接，避免重复下单
6. 如果存在已创建订单但未生成支付单，则重新生成支付单
7. 如果不存在订单，则先查询商品信息，再创建订单聚合
8. 领域服务调用仓储保存订单
9. 再调用支付宝接口创建预支付单
10. 更新订单支付信息并返回支付链接

## 6. 关键职责拆分

### 6.1 Controller 层

职责：

- 接收 HTTP 请求
- 组装入参
- 调用领域服务
- 返回支付链接或错误信息

### 6.2 Domain Service 层

职责：

- 控制下单主流程
- 校验是否存在未支付订单
- 组织订单聚合
- 调用仓储保存订单
- 调用支付能力创建预支付单

### 6.3 Repository 层

职责：

- 承担领域对象与持久化对象之间的转换
- 访问数据库
- 保存订单记录
- 更新支付状态

### 6.4 Port 层

职责：

- 对接商品服务等外部能力
- 提供领域需要的商品查询接口

## 7. 典型时序

### 首次下单

1. 查询未支付订单，结果为空
2. 远程查询商品信息
3. 构造订单聚合
4. 保存订单
5. 调用支付宝生成支付单
6. 更新订单支付信息
7. 返回支付链接

### 重复下单

1. 查询到已存在未支付订单
2. 直接返回原支付链接
3. 不重复创建订单

### 只有订单、未生成支付单

1. 查询到订单状态为创建中
2. 重新生成支付单
3. 回写支付信息
4. 返回支付链接

## 8. 后续检查点

建议再确认下面几项：

- `OrderRepository` 是否已经被 Spring 扫描到
- `IOrderDao` 的 MyBatis Mapper 是否正常注册
- 商品查询能力 `IProductPort` 是否也已注入成功
- 支付宝配置项是否完整

如果后续还有启动失败，优先看是不是其他实现类也缺少 `@Component` / `@Service` / `@Repository` 注解。
