# 购物车结算功能 — 设计文档与暂存点

> 日期：2026-09-04
> 状态：**设计完成，待实现**
> 分支：`group-buy-dev`

---

## 1. 需求背景

购物车（`cart` 表）已具备增删改查与选中能力，但目前**没有结算入口**。用户在购物车页面勾选商品后，无法将多个商品聚合为一笔订单并统一支付，只能逐个商品手动下单（走老的 `lock_order → confirm_order(productId)` 链路）。

**本次目标**：实现购物车结算，将用户勾选的多个商品聚合为一笔 `pay_order`，写入订单明细表 `pay_order_item`，统一发起支付宝支付。

---

## 2. 现有链路梳理

### 2.1 购物车 CRUD（已完成，不改动）

```
POST  /api/v1/cart/add              → addToCart
GET   /api/v1/cart/list             → listCart
POST  /api/v1/cart/update_quantity  → updateQuantity
POST  /api/v1/cart/toggle_check    → toggleCheck
POST  /api/v1/cart/remove           → removeFromCart
POST  /api/v1/cart/batch_remove     → batchRemove
POST  /api/v1/cart/clear            → clearCart
```

关键字段：`user_id, product_id, quantity, checked, status`，唯一键 `uk_user_product(user_id, product_id)`。

### 2.2 单商品下单（现有，需兼容）

```
lock_order
  → OrderLockService.lockOrder()
  → 插入 order_lock 表（status=LOCKED，15分钟过期）

confirm_order(productId, lockId)
  → AbstractOrderService.createOrder(userId, productId, lockId)
  → 校验锁 → 查商品 → 幂等复用检查(queryUnPayOrder) 
  → doSaveOrder → 插入 pay_order（product_id/product_name/total_amount=商品单价）
  → doPrepayOrder → 调支付宝 → 更新 pay_url + status=PAY_WAIT
  → 锁标记 CONFIRMED

支付宝异步回调
  → changeOrderPaySuccess(outTradeNo) → status=PAY_SUCCESS
```

`pay_order` 表：1行 = 1个商品 = 1次支付，**没有** `pay_order_item` 明细表。

## 3. 方案选型

### 方案对比

| 方案 | 思路 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. 新建 pay_order_item** | pay_order 做头表，明细写 item 表 | 标准电商做法，扩展性强，支持按件退款 | 需新建表 + 适配写入逻辑 | ✅ 采用 |
| B. 逐个创建 pay_order | 循环为每个商品创建独立订单 | 改动最小 | 无法聚合支付，用户体验差 | ❌ |
| C. JSON 字段存明细 | pay_order 加 JSON 列存商品列表 | 不加表 | 无法索引，无法按明细退款 | ❌ |

### 方案 A 核心设计

```
pay_order（头信息，新增可空商品字段标注）
├── total_amount  → 含义从"单商品价格"变为"汇总金额"
├── product_id    → 改为 nullable（多商品结算时为 null）
└── product_name  → 改为 nullable（多商品结算时为 null）

pay_order_item（新表，订单明细）
├── order_id      → pay_order.out_trade_no（非外键，业务关联）
├── product_id    → 商品ID
├── product_name  → 商品名称快照
├── quantity      → 数量
├── price         → 商品单价
└── total_amount  → 小计（price × quantity）
```

## 4. SQL 定义

文件位置：`data/sql/pay_order_item.sql`

```sql
-- 1. 新建订单明细表
CREATE TABLE IF NOT EXISTS `pay_order_item` (
    `id`           bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '自增ID',
    `order_id`     varchar(64)     NOT NULL COMMENT '商户订单号(pay_order.out_trade_no)',
    `product_id`   bigint          NOT NULL COMMENT '商品ID',
    `product_name` varchar(128)    NOT NULL COMMENT '商品名称(快照)',
    `quantity`     int             NOT NULL DEFAULT 1 COMMENT '数量',
    `price`        decimal(10,2)   NOT NULL COMMENT '商品单价',
    `total_amount` decimal(10,2)   NOT NULL COMMENT '小计金额(price × quantity)',
    `create_time`  datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`  datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`) USING BTREE,
    KEY `idx_order_id` (`order_id`) USING BTREE
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci ROW_FORMAT = DYNAMIC COMMENT ='订单明细表';

-- 2. pay_order 商品字段改为可空
ALTER TABLE `pay_order`
    MODIFY COLUMN `product_id`   varchar(64)  DEFAULT NULL COMMENT '商品ID(单商品下单填写，多商品结算为空)',
    MODIFY COLUMN `product_name` varchar(128) DEFAULT NULL COMMENT '商品名称(单商品下单填写，多商品结算为空)';
```

## 6. 结算核心流程（设计）

```
POST /api/v1/cart/checkout
  Body: { "cartIds": [1, 3, 5] }

  ① CartService.checkoutFromCart(userId, cartIds)
     ├─ 查 cart 表，校验 cartIds 属于该用户、checked=1、status=1
     ├─ 查商品信息（productPort），校验商品存在且上架
     ├─ 计算每项：quantity × price → itemAmount，汇总 totalAmount
     ├─ lock_order → 获取 lockId
     │
  ② 调 OrderService.createCartOrder(userId, items, lockId)
     ├─ 校验 lockId（同现有逻辑）
     ├─ doSaveOrder → 插入 pay_order（totalAmount=汇总金额，product_id=null）
     ├─ 批量插入 pay_order_item（每个商品一条）
     ├─ doPrepayOrder → 调支付宝
     └─ 更新 pay_url + status=PAY_WAIT
  ③ 返回 { outTradeNo, payUrl }
  ④ 支付成功回调后：清除已结算的 cart 记录（checked=1 且已付款的）
```

## 7. 待决策事项

| 问题 | 选项 A | 选项 B | 当前倾向 |
|------|--------|--------|----------|
| 单商品下单是否也写 item 表 | 统一写（1条明细） | 老链路不改，只给购物车结算写 | 待定（A 更统一，B 改动更小） |
| 支付宝回调后清理购物车时机 | 异步（MQ 消费时清理） | 同步（支付成功时直接删） | 待定 |
| 结算接口是否复用 lock_order | 复用（前端先锁单再调 checkout） | checkout 内部自动锁单（对前端更友好） | 倾向内部自动锁单 |

---

## 8. 风险与注意事项

- `pay_order` 的 `ALTER TABLE MODIFY` 需在低峰执行，生产环境注意锁表时间
- `product_id` 在 `pay_order` 中是 `varchar(64)`，而 `pay_order_item` 中是 `bigint`，需保持类型映射一致
- 已有的单商品订单历史数据不受影响（`product_id/product_name` 仍有值，`pay_order_item` 中无历史数据）
- 支付宝异步回调的退款扫描任务（`queryTimeOutCloseOrderList`）目前只处理单商品，后续需适配多商品退款
