# 支付链路说明

本文只描述当前仓库里已经存在的支付宝支付链路，不新增代码。

## 1. 链路目标

实现“下单 -> 预下单 -> 支付回调 -> 本地订单更新 -> 定时补偿”的完整支付闭环。

## 3. 具体流程

### 3.1 创建支付单

1. 前端提交 `userId + productId`
2. `AliPayController.createPayOrder()` 接收请求
3. `orderService.createOrder()` 进入领域服务
4. `AbstractOrderService` 先查是否已有未支付订单
5. 如果已有 `PAY_WAIT` 订单，直接返回原支付链接
6. 如果已有 `CREATE` 订单，则补创建支付单
7. 如果没有订单，则查询商品信息并创建新订单
8. 订单入库后，调用支付宝网页支付接口生成 `payUrl`
9. 更新本地订单状态为 `PAY_WAIT`
10. 返回 `payUrl` 给前端跳转

关键代码：

- [AliPayController.java](../../../s-pay-mall-ddd-trigger/src/main/java/cn.bugstack.trigger/http/AliPayController.java)
- [AbstractOrderService.java](../../../s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/order/service/AbstractOrderService.java)
- [OrderService.java](../../../s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/order/service/OrderService.java)

### 3.2 支付回调

1. 支付宝异步回调到 `POST /api/v1/alipay/pay_notify`
2. `AliPayController` 先判断 `trade_status`
3. 组装参数并做 RSA2 验签
4. 验签通过后，调用 `orderService.changeOrderPaySuccess(out_trade_no)`
5. `OrderRepository` 更新订单状态为 `PAY_SUCCESS`
6. 同时构造 `PaySuccessMessageEvent` 并通过 `EventBus` 发布
7. 监听器 `OrderPaySuccessListener` 接收事件，做后续扩展动作

关键代码：

- [OrderRepository.java](../../../s-pay-mall-ddd-infrastructure/src/main/java/cn/bugstack/infrastructure/adapter/repository/OrderRepository.java)
- [PaySuccessMessageEvent.java](../../../s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/order/event/PaySuccessMessageEvent.java)

### 3.3 定时补偿

项目里有两个补偿任务：

- `NoPayNotifyOrderJob`
- `TimeoutCloseOrderJob`

#### 未收到回调的补偿

1. 定时查找 `PAY_WAIT` 且超过 1 分钟的订单
2. 调用支付宝查询接口确认交易状态
3. 如果支付宝已成功，则补写本地订单成功状态

对应实现：

- [NoPayNotifyOrderJob.java](../../../s-pay-mall-ddd-trigger/src/main/java/cn.bugstack.trigger/job/NoPayNotifyOrderJob.java)

#### 超时关单

1. 定时查找 `PAY_WAIT` 且超过 30 分钟的订单
2. 调用 `changeOrderPayClose(orderId)`
3. 将订单状态更新为 `CLOSE`

对应实现：

- [TimeoutCloseOrderJob.java](../../../s-pay-mall-ddd-trigger/src/main/java/cn.bugstack.trigger/job/TimeoutCloseOrderJob.java)

## 4. 订单状态流转

当前状态主要是：

- `CREATE`：订单刚创建
- `PAY_WAIT`：等待支付
- `PAY_SUCCESS`：支付成功
- `DEAL_DONE`：交易完成
- `CLOSE`：超时关单

对应枚举见：

- [OrderStatusVO.java](../../../s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/order/model/valobj/OrderStatusVO.java)

## 5. 这个链路的特点

- 订单先落库，再生成支付单
- 支付回调是主成功路径
- 定时任务负责兜底
- 支付成功后通过事件解耦后续动作

## 6. 你接手时要注意的点

- 现在的 `ProductRPC` 只是模拟商品查询，不是真实商品库
- 支付回调处理依赖验签，不能直接信任请求参数
- `pay_order` 表是支付链路的核心持久化表
