# 登录架构问答总结

这份文档整理了你前面问到的几个问题，目的是把 `s-pay-mall-ddd-cc` 里微信扫码登录这条链路的分层、实现位置和当前报错原因一次讲清楚。

## 1. 这个项目到底是什么架构

`s-pay-mall-ddd-cc` 不是传统 MVC 的单层 `Controller -> ServiceImpl -> DAO` 写法，而是一个多模块 DDD 分层项目。

模块大致分成：

- `s-pay-mall-ddd-trigger`
- `s-pay-mall-ddd-app`
- `s-pay-mall-ddd-domain`
- `s-pay-mall-ddd-infrastructure`
- `s-pay-mall-ddd-api`
- `s-pay-mall-ddd-types`

对应的依赖方向可以理解为：

```text
trigger -> app -> domain
trigger -> infrastructure -> domain
app -> domain
infrastructure -> domain
domain -> types
api -> types
```

这里的核心原则是：**外层依赖内层，内层不要反向依赖外层**。

## 2. `ILoginService` 和 `ILoginPort` 分别干什么

这两个接口虽然都有 `createQrCodeTicket()`，但职责不同。

### `ILoginService`

位置：

- [ILoginService.java](/D:/code/s-pay-mall-ddd-cc/s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/auth/service/ILoginService.java)

它是**领域服务接口**，给 `trigger` 层调用，表达的是“登录业务能做什么”。

也就是说，`Controller` 不应该直接碰微信 API，而是先调用 `ILoginService`。

### `ILoginPort`

位置：

- [ILoginPort.java](/D:/code/s-pay-mall-ddd-cc/s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/auth/adapter/port/ILoginPort.java)

它是**领域端口接口**，表达的是“登录业务需要外部系统提供什么能力”。

例如：

- 创建微信二维码 ticket
- 发送微信模板消息

## 3. `impl` 实现到底在哪里

如果你习惯 MVC 的 `ServiceImpl` 思维，在这个项目里要换成“分层实现”的思路。

### 业务实现

`ILoginService` 的实现应该在 `domain` 层，比如：

- `WeixinLoginService`

这个类负责业务编排，内部再去调用 `ILoginPort`。

### 外部系统实现

`ILoginPort` 的实现已经在 `infrastructure` 层：

- [LoginPort.java](/D:/code/s-pay-mall-ddd-cc/s-pay-mall-ddd-infrastructure/src/main/java/cn/bugstack/infrastructure/adapter/port/LoginPort.java)

它负责真正调用微信接口、拿 `access_token`、创建二维码 ticket、发送模板消息。

## 4. 当前项目的登录调用链

这条链路可以按下面理解：

```text
LoginController
  -> ILoginService
  -> LoginService 的实现类
  -> ILoginPort
  -> LoginPort
  -> 微信公众平台 API
```

对应到功能上：

- `Controller` 负责接收 HTTP 请求
- `Service` 负责业务编排
- `Port` 负责对接外部系统
- `Infrastructure` 负责真正发请求

## 5. 你现在报错的原因

你遇到的报错是：

```text
No qualifying bean of type 'cn.bugstack.domain.auth.service.ILoginService'
```

这个错误的意思很直接：

- Spring 找到了 `LoginController`
- 但找不到 `ILoginService` 的实现 bean

也就是说，当前项目里至少存在以下问题之一：

1. `ILoginService` 只有接口，没有实现类
2. 实现类存在，但没有加 `@Service`
3. 实现类存在，但包路径没有被 Spring 扫描到

根据我看到的代码，你现在更像是第 1 种：

- `trigger` 层已经注入了 `ILoginService`
- `domain` 层只有 `ILoginService` 接口
- 但没有 `implements ILoginService` 的服务实现类

## 6. 为什么 `LoginPort` 不能代替 `ILoginService`

因为它们不是同一个层的契约。

- `ILoginService` 是给上层调用的业务接口
- `ILoginPort` 是给下层实现的外部能力接口

Spring 也不会把一个 `ILoginPort` bean 当成 `ILoginService` 来注入。

所以：

- `LoginController` 需要的是 `ILoginService`
- `LoginService` 的实现类再去依赖 `ILoginPort`
- `LoginPort` 负责具体调用微信接口

## 7. 你应该怎么修

最直接的修法是补一个领域服务实现类，例如：

- `../../../s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/auth/service/WeixinLoginService.java`

这个类需要：

- `@Service`
- `implements ILoginService`
- 注入 `ILoginPort`
- 实现 `createQrCodeTicket()`
- 实现 `checkLogin()`
- 实现 `saveLoginState()`

## 8. 一句话总结

这个项目不是“一个 `impl` 解决所有问题”的 MVC 写法，而是：

- `trigger` 接请求
- `domain` 管业务
- `infrastructure` 管外部系统

你现在的报错，本质上就是：**`LoginController` 依赖了 `ILoginService`，但项目里还没有可注入的 `ILoginService` 实现类。**
