# 生产需求单软编码执行接口说明

本文档说明将 `ToothbrushProductionJob` 中牙刷、塑料、木头等硬编码改为生产需求单驱动后，新增的后端内部接口分别负责什么。

这些接口不是前端 HTTP 接口，而是后端内部的 Service / Repository 接口，主要供 `ProductionOrderJob` 定时任务调用。

## 目标

原来的生产任务把生产对象和原料写死在 Job 中：

```java
private static final Long TOOTHBRUSH_PRODUCT_ID = 1L;
private static final Long FINISHED_PRODUCT_WAREHOUSE_ID = 1L;
private static final Integer PRODUCTION_QTY = 100;

private static final Long PLASTIC_MATERIAL_ID = 2L;
private static final Integer PLASTIC_QTY = 10;

private static final Long WOOD_MATERIAL_ID = 3L;
private static final Integer WOOD_QTY = 10;
```

软编码后的目标是：

```text
定时任务只负责触发
        ↓
查询 production_order 待处理生产需求单
        ↓
根据 production_order_material 原料明细执行备料
        ↓
原料锁定、出库
        ↓
成品入库
        ↓
更新生产需求单状态
```

## 状态约定

`production_order.status`：

```text
0 待处理
1 处理中
2 已完成
3 失败
```

`production_order_material.status`：

```text
0 待处理
1 已锁定
2 已出库
3 已释放
```

## IProductionOrderService

路径：

```text
s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/production/service/IProductionOrderService.java
```

### executeCreatedOrders

```java
void executeCreatedOrders();
```

作用：批量执行待处理生产需求单。

典型调用方是定时任务：

```text
ProductionOrderJob.exec()
        ↓
productionOrderService.executeCreatedOrders()
        ↓
查询 status = 0 的生产需求单
        ↓
逐个调用 executeOrder(orderId)
```

这个方法让 Job 不再关心具体生产什么商品，也不关心需要哪些原料。

### executeOrder

```java
void executeOrder(Long productionOrderId);
```

作用：执行某一张指定的生产需求单。

核心流程：

```text
1. 根据 productionOrderId 查询生产需求单
2. 校验生产单是否存在
3. 校验生产单状态是否为待处理 status = 0
4. 校验是否存在原料明细
5. 更新生产单状态为处理中 status = 1
6. 遍历 production_order_material 原料明细
7. 为每种原料创建原料库存分配单
8. 锁定原料库存
9. 回写 allocationNo 到生产单原料明细
10. 自动原料出库
11. 成品入库
12. 更新生产单状态为已完成 status = 2
13. 如果失败，释放已锁定原料，并把生产单标记为失败 status = 3
```

这个方法是通用生产执行逻辑，替代原来 `ToothbrushProductionJob` 里写死的生产流程。

## IProductionOrderRepository

路径：

```text
s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/production/repository/IProductionOrderRepository.java
```

### queryCreatedOrders

```java
List<ProductionOrderAggregate> queryCreatedOrders(Integer limit);
```

作用：查询待处理生产需求单。

对应数据库筛选条件：

```sql
where status = 0
  and is_del = 0
order by id asc
limit #{limit}
```

这个方法供 `executeCreatedOrders()` 使用。`limit` 用于限制每次定时任务最多处理多少张生产单，避免一次扫描执行过多数据。

### updateOrderStatus

```java
void updateOrderStatus(Long orderId, Integer status);
```

作用：更新生产需求单主表状态。

执行过程中常见状态流转：

```text
待处理 status = 0
        ↓
处理中 status = 1
        ↓
已完成 status = 2
```

失败时：

```text
待处理 status = 0
        ↓
处理中 status = 1
        ↓
失败 status = 3
```

### updateMaterialAllocationNo

```java
void updateMaterialAllocationNo(Long orderMaterialId, String allocationNo, Integer status);
```

作用：更新生产需求单原料明细。

主要更新字段：

```text
production_order_material.allocation_no
production_order_material.status
production_order_material.update_time
```

其中 `allocationNo` 是调用原料库存分配服务生成的备料单号。

这个字段用于建立关系：

```text
生产需求单原料明细
        ↓
原料库存分配单
```

后续查询生产需求单详情时，可以知道每种原料对应哪一张备料单，以及当前执行到哪个状态。

## ProductionOrderRepository 实现职责

路径：

```text
s-pay-mall-ddd-infrastructure/src/main/java/cn/bugstack/infrastructure/repository/ProductionOrderRepository.java
```

Repository 层主要负责领域对象和数据库对象之间的转换。

### queryCreatedOrders 实现逻辑

```text
1. 校验 limit
2. 调用 productionOrderDao.queryByStatus(0, limit)
3. 遍历查询到的生产单
4. 根据 production_order.id 查询 production_order_material 明细
5. 将 PO 转换为 ProductionOrderAggregate
6. 返回聚合列表
```

### updateOrderStatus 实现逻辑

```text
1. 校验 orderId
2. 校验 status
3. 调用 productionOrderDao.updateStatus(orderId, status)
```

### updateMaterialAllocationNo 实现逻辑

```text
1. 校验生产单原料明细 ID
2. 校验 allocationNo
3. 校验 status
4. 调用 productionOrderMaterialDao.updateAllocationNo(...)
```

## MyBatis Mapper

### production_order_mapper.xml

新增查询待处理生产单：

```xml
<select id="queryByStatus" resultMap="productionOrderMap">
    select id, order_no, product_id, product_quantity, warehouse_id, status, is_del, create_time, update_time
    from production_order
    where status = #{status}
    and is_del = 0
    order by id asc
    limit #{limit}
</select>
```

新增更新生产单状态：

```xml
<update id="updateStatus">
    update production_order
    set status = #{status}, update_time = now()
    where id = #{id}
    and is_del = 0
</update>
```

### production_order_material_mapper.xml

新增更新原料明细分配单号和状态：

```xml
<update id="updateAllocationNo">
    update production_order_material
    set allocation_no = #{allocationNo},
    status = #{status},
    update_time = now()
    where id = #{id}
    and is_del = 0
</update>
```

## 总结

新增接口的核心目的：

```text
executeCreatedOrders()
    批量找待执行生产单

executeOrder(id)
    执行某一张生产单

queryCreatedOrders(limit)
    从数据库查待处理生产单

updateOrderStatus(...)
    更新生产单主状态

updateMaterialAllocationNo(...)
    记录原料备料单号和原料执行状态
```

通过这些接口，生产任务从“牙刷专用 Job”变成“生产需求单驱动的通用 Job”。
