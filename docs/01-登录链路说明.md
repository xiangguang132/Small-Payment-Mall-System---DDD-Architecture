# 登录链路说明

本文只描述当前仓库里已经存在的微信扫码登录链路，不新增代码。

## 1. 链路目标

实现用户扫码登录，核心流程是：

1. 前端请求二维码 ticket
2. 微信公众号生成扫码二维码
3. 用户扫码后，微信回调服务端
4. 服务端保存登录状态
5. 前端轮询 ticket，拿到 openid/token

## 2. 入口与出口

### HTTP 入口

- `GET /api/v1/login/weixin_qrcode_ticket`
- `GET /api/v1/login/check_login?ticket=...`
- `GET/POST /api/v1/weixin/portal/receive`

## 3. 具体流程

### 3.1 获取 ticket

1. 前端调用 `GET /api/v1/login/weixin_qrcode_ticket`
2. `LoginController` 调用 `ILoginService.createQrCodeTicket()`
3. `WeixinLoginService` 委托 `ILoginPort.createQrCodeTicket()`
4. `LoginPort` 先取 `weixinAccessToken` 缓存
5. 如果缓存没有 token，则通过微信接口获取
6. 再调用微信生成二维码 ticket 接口
7. 返回 ticket 给前端

关键代码：

- [LoginController.java](../s-pay-mall-ddd-trigger/src/main/java/cn.bugstack.trigger/http/LoginController.java)
- [WeixinLoginService.java](../s-pay-mall-ddd-domain/src/main/java/cn/bugstack/domain/auth/service/WeixinLoginService.java)
- [LoginPort.java](../s-pay-mall-ddd-infrastructure/src/main/java/cn/bugstack/infrastructure/adapter/port/LoginPort.java)

### 3.2 微信扫码回调

1. 微信服务器先调用 `GET /api/v1/weixin/portal/receive` 做验签
2. 验签通过后，微信会把扫码消息推送到 `POST /api/v1/weixin/portal/receive`
3. `WeixinPortalController` 将 XML 解析成 `MessageTextEntity`
4. 当消息类型是 `event` 且事件是 `SCAN` 时，调用 `loginService.saveLoginState(ticket, openid)`
5. `WeixinLoginService` 将 `ticket -> openid` 放入 `openidToken` 缓存
6. 同时发送微信模板消息，提示登录成功

关键代码：

- [WeixinPortalController.java](../s-pay-mall-ddd-trigger/src/main/java/cn.bugstack.trigger/http/WeixinPortalController.java)
- [XmlUtil.java](../s-pay-mall-ddd-types/src/main/java/cn/bugstack/types/sdk/weixin/XmlUtil.java)
- [SignatureUtil.java](../s-pay-mall-ddd-types/src/main/java/cn/bugstack/types/sdk/weixin/SignatureUtil.java)
- [MessageTextEntity.java](../s-pay-mall-ddd-types/src/main/java/cn/bugstack/types/sdk/weixin/MessageTextEntity.java)

### 3.3 前端轮询登录结果

1. 前端带着 ticket 请求 `GET /api/v1/login/check_login`
2. `LoginController` 调用 `loginService.checkLogin(ticket)`
3. `WeixinLoginService` 从 `openidToken` 缓存中查询
4. 查到则返回登录成功信息
5. 查不到则返回未登录

## 4. 这个链路的特点

- 登录状态不落库，依赖内存缓存
- `ticket` 是临时状态标识
- 微信回调是登录成功的唯一写入口
- 代码里已经把微信 SDK 调用、验签、XML 转换拆开了

## 5. 你接手时要注意的点

- `openidToken` 是内存缓存，应用重启会丢失登录状态
- 微信 access token 也在内存缓存里，有过期时间
- 当前实现更偏演示和教学，不是完整的生产级登录系统
