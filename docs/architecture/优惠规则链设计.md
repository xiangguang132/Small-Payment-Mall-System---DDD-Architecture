# 优惠规则链设计

> 日期：2026-08-27
> 状态：设计稿，待确认后实施
> 目标：让试算支持拼团、优惠券、积分等优惠按规则链叠加，而不是当前只支持一条拼团折扣。

## 1. 当前现状

当前试算入口是 `GroupBuyTrialService`，内部使用策略树：

```text
GroupBuyTrialService
  -> RootNode
    -> SwitchNode
      -> MarketNode
        -> TagNode
          -> EndNode
```

当前关键限制：

- `RootNode` 强制要求 `activityId` 非空，无法表达“商品不走拼团优惠”的场景。
- `MarketNode` 只查询并计算一条拼团折扣。
- 现有 `GroupBuyTrialResult` 只有一组 `deductionPrice` / `payPrice`，无法表达多优惠明细。
- 当前结构是“策略树”，不是“优惠规则链”，新增一种优惠时会破坏现有逻辑或需要反复改节点。
- `SwitchNode` 当前通过 `IGroupBuyActivityRepository` 调用 DCC 开关，但 `DCCService` 中的 `downgradeSwitch` / `cutRange` 实际是全局配置，不只是拼团活动专属。

## 2. 设计目标

- 支持拼团、优惠券、积分等优惠按顺序执行。
- 支持优惠之间可叠加、不可叠加、有优先级、有前置条件。
- 支持部分商品不走拼团，直接走券、积分或普通价格。
- 新增优惠规则时，尽量只新增一个规则实现，不改老规则。
- 保留当前策略树作为外层编排，规则链作为价格计算核心。

## 3. 目标流程

```text
GroupBuyTrialService
  -> RootNode
    -> SwitchNode（所有试算请求）
      -> MarketNode
        - 查询商品，必查
        - 查询拼团活动/折扣，可选
        - 执行 TrialRuleChain
        - 写回 DynamicContext
      -> TagNode
      -> EndNode
```

说明：

- 所有试算请求都先走 `SwitchNode` 做全局降级和切量，不依赖是否属于拼团活动。
- 降级/切量通过独立开关仓储访问 DCC 配置，不再放在 `IGroupBuyActivityRepository`。
- 没有拼团活动时，`MarketNode` 仍会执行规则链。
- `GroupBuyTrialRule.match()` 在无拼团折扣时返回 `false`，不会报错。
- `CouponTrialRule`、`PointsTrialRule` 可以继续执行并叠加。

## 4. 核心抽象

### 4.1 规则接口

```java
public interface ITrialRule {

    TrialRuleTypeEnum getRuleType();

    boolean match(TrialRuleContext context);

    TrialRuleResult calculate(TrialRuleContext context);
}
```

### 4.2 规则链执行器

```java
for (ProductPromotionRuleEntity rule : productRules) {
    ITrialRule handler = ruleMap.get(rule.getRuleType());

    if (handler.match(context)) {
        TrialRuleResult result = handler.calculate(context);
        context.apply(result);

        if (!result.isStackable()) {
            break;
        }
    }
}
```

### 4.3 试算上下文

`TrialRuleContext` 至少包含：

- `userId`
- `productId`
- `product`
- `activity`，允许为空
- `discount`，允许为空
- `originalPrice`
- `currentPrice`
- `selectedCouponIds`
- `selectedCoupons`
- `points`
- `appliedRuleResults`

### 4.4 规则实现

- `GroupBuyTrialRule`：继续复用现有 `IGroupBuyDiscountService` 和 `IGroupBuyDiscountRepository`。
- `CouponTrialRule`：按用户券、券模板、商品适用范围计算券优惠。
- `PointsTrialRule`：按用户积分、积分抵扣比例计算积分优惠。
- 后续会员价、满减、平台补贴等，都按同一个 `ITrialRule` 扩展。

### 4.5 降级/切量

- `SwitchNode` 对所有试算请求执行全局降级和切量，不区分拼团、券还是积分试算。
- 新增 `ITrialSwitchRepository` 访问 `DCCService`，避免继续通过 `IGroupBuyActivityRepository` 承载 DCC 开关语义。
- `IGroupBuyActivityRepository` 中的 `downgradeSwitch()` / `cutRange()` 不再作为试算开关的调用入口。

## 6. 数据库设计

### 6.1 product_promotion_rule

商品优惠规则映射，决定商品走哪些规则、执行顺序和是否可叠加：

- `id`
- `product_id`
- `rule_type`：`GROUP_BUY`、`COUPON`、`POINTS`
- `rule_code`：拼团 `discountId`、券 `couponId` 或积分配置编码
- `priority`：执行顺序
- `stackable`：是否可叠加
- `status`
- `create_time`
- `update_time`

### 6.2 coupon

优惠券模板：

- `id`
- `coupon_id`
- `coupon_name`
- `coupon_type`：直减、折扣、满减
- `discount_value`
- `threshold_amount`
- `scope_type`：全场、指定商品、指定分类
- `status`
- `start_time`
- `end_time`

### 6.3 user_coupon

用户已领取的券：

- `id`
- `user_id`
- `coupon_id`
- `status`：未使用、已使用、已过期
- `order_id`
- `use_time`
- `expire_time`

### 6.4 points

用户积分账户：

- `id`
- `user_id`
- `available_points`
- `frozen_points`
- `update_time`

## 7. 需要修改的文件

- `RootNode`：允许 `activityId` 为空，要求 `productId` 必填；无拼团活动时仍进入 `SwitchNode` 做统一降级/切量。
- `SwitchNode`：所有试算请求都先做降级和切量，不依赖是否拼团；改注入 `ITrialSwitchRepository`。
- `IGroupBuyActivityRepository`：移除 `downgradeSwitch()` / `cutRange()` 的拼团语义包装，或保留为兼容但 `SwitchNode` 不再使用。
- `MarketNode`：商品必查、拼团活动/折扣可选，并调用 `TrialRuleChain`。
- `EndNode`：没有拼团折扣时返回原价或规则链结果，不再返回不可见。
- `DefaultActivityStrategyFactory.DynamicContext`：增加当前价、已命中规则、券、积分等字段。
- 领域 `GroupBuyTrialRequest`：增加 `couponIds`、`usePoints`，允许 `activityId` 为空。
- 领域 `GroupBuyTrialResult`：增加 `ruleDetails` 等优惠明细。
- API `GroupBuyTrialRequest`：同步增加券和积分参数。
- API `GroupBuyTrialResponse`：增加优惠明细返回。
- `GroupBuyController`：同步透传新参数和返回字段。

## 8. 关键行为变化

- 降级和切量作用于整个试算规则链，不只是拼团活动。
- 商品没拼团活动时，走普通试算，`GroupBuyTrialRule.match()` 返回 `false`。
- 商品同时配置拼团和券时，按 `priority` 顺序执行，例如先拼团后券。
- 某条规则不可叠加时，`TrialRuleChain` 停止后续规则。
- 最终价格按“前序优惠后金额”继续计算，避免多条规则都按原价扣减导致金额异常。
- 优惠顺序和基数规则必须明确，否则同一订单可能出现不同结果。

## 10. 后续扩展

- 新增会员价规则：新增 `MemberTrialRule`，配置商品规则映射。
- 新增满减规则：新增 `FullReductionTrialRule`。
- 新增平台补贴：新增 `SubsidyTrialRule`。
