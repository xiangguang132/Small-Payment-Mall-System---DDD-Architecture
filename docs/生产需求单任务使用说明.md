# 生产需求单任务使用说明

本文档说明如何使用 `ProductionOrderJob` 自动执行生产需求单。

## 当前执行方式

当前没有新增手动执行 HTTP 接口。

生产需求单执行方式是：

```text
开启定时任务
        ↓
定时任务扫描待处理生产需求单
        ↓
按 id 从小到大执行
```

也就是说，只要任务开启，它会自动执行数据库中满足条件的生产需求单。

## 开启任务

在配置文件中开启：

```yaml
production:
  order:
    job:
      enabled: true
      cron: 0 0/1 * * * ?
```

含义：

```text
enabled: true
    开启生产需求单定时任务

cron: 0 0/1 * * * ?
    每 1 分钟执行一次
```

如果不配置，默认值是：

```text
enabled = false
cron = 0 0/1 * * * ?
```

也就是说，默认不会自动执行生产需求单。

## 会执行哪一张生产需求单

定时任务执行的是所有待处理生产需求单。

筛选条件：

```sql
where status = 0
  and is_del = 0
order by id asc
limit 10
```

也就是说，每次任务最多执行 10 张单，并且按 `id` 从小到大执行。

示例：

```text
id = 3, status = 2  已完成
id = 5, status = 0  待处理
id = 7, status = 0  待处理
id = 9, status = 1  处理中
id = 12, status = 0 待处理
```

开启任务后会执行：

```text
id = 5
id = 7
id = 12
```

不会执行：

```text
id = 3，因为已经完成
id = 9，因为正在处理中
```

## 如何只执行某一张单

当前没有指定执行某一张单的 HTTP 接口。

如果只想让定时任务执行某一张生产需求单，可以保证只有这一张单满足：

```text
status = 0
is_del = 0
```

其他暂时不想执行的待处理单，可以先不要创建，或者临时把状态改成非 `0`。

例如只想执行 `id = 12`：

```sql
update production_order
set status = 3, update_time = now()
where status = 0
  and id <> 12;

update production_order
set status = 0, update_time = now()
where id = 12
  and is_del = 0;
```

然后开启任务即可。

注意：上面只是临时测试用法。正式业务中不建议随意手动改生产单状态。

## 执行前检查

执行前确认这几类数据是正常的：

```text
1. production_order 存在待处理单，status = 0
2. production_order.is_del = 0
3. production_order_material 有原料明细
4. 原料 material 是启用状态
5. 原料库存充足
6. 成品 product 是上架状态
7. 入库 warehouse 是启用状态
```

如果原料库存不足，生产单会被标记为失败：

```text
production_order.status = 3
```

如果已经锁定了部分原料，系统会尝试释放已经锁定的原料。

## 执行后的状态变化

成功时：

```text
production_order.status:
0 待处理
    ↓
1 处理中
    ↓
2 已完成
```

原料明细：

```text
production_order_material.status:
0 待处理
    ↓
1 已锁定
    ↓
2 已出库
```

失败时：

```text
production_order.status:
0 待处理
    ↓
1 处理中
    ↓
3 失败
```

如果原料已经锁定但后续失败：

```text
production_order_material.status:
1 已锁定
    ↓
3 已释放
```

## 任务调用链

```text
ProductionOrderJob.exec()
        ↓
IProductionOrderService.executeCreatedOrders()
        ↓
IProductionOrderRepository.queryCreatedOrders(10)
        ↓
IProductionOrderService.executeOrder(orderId)
        ↓
IMaterialStockAllocationService.create(...)
        ↓
IMaterialStockAllocationService.lock(...)
        ↓
IMaterialStockAllocationService.autoOutbound(...)
        ↓
IStockService.inbound(...)
        ↓
IProductionOrderRepository.updateOrderStatus(...)
```

## 注意事项

当前实现是自动扫描模式，不是指定单执行模式。

如果数据库里有多张 `status = 0` 的生产需求单，开启任务后它们都会被执行。

如果后续需要明确执行某一张单，建议新增接口：

```http
POST /api/v1/production-order/{id}/execute
```

这个接口可以直接调用：

```java
productionOrderService.executeOrder(id);
```
